## 1. 要回答的問題

m 的分母是「機隊付費 token × 2025 機隊單價」，機隊 token 由推論支出往回推：推論支出 ÷ 計價倍數 ÷ 持有成本 × …。所以這裡需要的是**服務用戶（付費＋免費）的推論算力支出，所有供應商合計，以 OpenAI 實付價計**。研究用推論（強化學習 rollout、評測、合成資料）不產生對外 token，不應計入。

## 3. 調和計算

### 3.1 付 Microsoft 172 億的橋接

| 項目 | 金額 | 說明 |
|---|---|---|
| OpenAI 帳上付 Microsoft 合計（F5） | 17.21 | 查核數 |
| Microsoft 稱為「推論」的全年（F3） | 12.6 | 外推數 |
| 其中 OpenAI 列營業成本（F5） | 6.05 | 上限：還可能含營收分成，見 3.3 |
| **Microsoft 稱推論、OpenAI 不列營業成本的部分** | **6.55** | 只能落在研發（10.59）或行銷（0.53） |
| 隱含 Azure 上的非推論支出（訓練等） | 4.61 | 17.21 − 12.6 |

兩份帳的總額是相容的（12.6 < 17.2），所以 126 億**不一定是錯的數字**；錯的是把它當成「服務用戶的推論」。Microsoft 前三季 8.67 已經比 OpenAI 全年營業成本付 Microsoft 的 6.05 多 2.6（1.43 倍），這個差距不靠第四季外推就成立。

### 3.2 2024 年同口徑對照（本檔新增的關鍵證據）

| 年度 | Microsoft 端「推論」 | OpenAI 端推論 | 倍數 |
|---|---|---|---|
| 2024 | 3.77（F2） | 1.8–2.0（F8，投資人文件，與研究、訓練分列） | 1.9–2.1 |
| 2025 | 12.6（F3） | 6.05（F5，營業成本付 Microsoft） | 2.08 |

- 兩年的倍數幾乎相同（約 2.1），表示差距是**系統性的口徑差異**，不是一次性的錯誤或第四季外推造成。
- 2024 年 OpenAI 自己的文件把訓練 3、研究 1–2、推論 1.8 分開列；Microsoft 端同年「推論」3.77 已超過 OpenAI 的推論 1.8，多出約 1.8–2.0，和 OpenAI 的研究算力同量級。這支持「Microsoft 的推論 SKU 包含 OpenAI 列為研究的推論類工作負載」（v5.36A 補充的解釋 (a)）。
- 成長率也對得上：OpenAI 端 2025 推論「約 4 倍」（F7），2.0 × 4.2＝8.4；Microsoft 端 3.77 → 12.6 是 3.3 倍。

另一方向：行銷付 Microsoft 0.53 可能是免費層推論（部分公司把免費層列行銷），可加回上限。

## 4. 獨立分析

### 4.1 三個待查問題的答案

| 問題（交接檔） | 結論 | 把握 |
|---|---|---|
| Azure 帳單是否含研發／實驗算力？ | **是，最可能。** 兩年倍數皆約 2.1；2024 年多出的金額與 OpenAI 自列的研究算力同量級；2025 年多出的 6.55 只能落在研發 10.59 | 中：Microsoft 文件未公開，分項無法逐筆核對 |
| 是否含抵用金？ | **不影響調和方向。** 抵用金被消耗時 OpenAI 仍需認列費用（查核財報 17.2 已含）；若 Microsoft 文件以牌價計、OpenAI 以折扣價付，會讓 Microsoft 端偏高，方向同上 | 低：抵用金規模與計價未找到 |
| 是否含其他供應商？ | **不含**（The Register）。但營業成本 7.5 已含所有供應商，非 Microsoft 只有 1.45；其他供應商的服務推論不大，不足以把服務推論推到 12.6 | 中高：來自查核數 |

### 4.2 誘因與反向檢驗

- **OpenAI 端（84、88 億）**有呈現較佳毛利的誘因 → 可能低報服務成本。但查核數 75 億（營業成本含所有供應商）比 84 億更低，所以這個誘因不足以推翻「服務推論遠低於 126 億」。
- **Microsoft 端（126 億）**是交易對手的權責帳，比 OpenAI 的敘述更不受 OpenAI 誘因影響；但文件經 Zitron 轉述，且 Microsoft 本身說「不太正確」。
- **反向假設**：如果 126 億真的全是服務推論，則 OpenAI 有約 6.5 億×10（65 億）的服務成本列在研發，查核財報的毛利率會被高估約 50 個百分點。查核報表出現這麼大的分類錯誤可能性低；另外 2024 年 OpenAI 自己的文件就已把研究與推論分開，倍數相同。此假設不成立的把握為中高。
- **仍有一種情況會讓 126 億部分成立**：新產品（例如 2025-09 底上線的 Sora app）的服務推論若在上線初期列研發，會讓真實服務推論高於營業成本。規模未知；第四季才影響，且只有一季。

### 4.3 物理面對照（[P]）

依 E259，用 126 億時支出路線服務 GW 由約 0.74 升到約 1.1。這個數字本身無法判斷對錯（OpenAI 2025 年底總算力規模的公開數字多為 OpenAI 自述），所以物理面在本題**不是決定性證據**，只記錄。

## 5. 評估

| 命題 | 判定 | 依據 |
|---|---|---|
| 126 億不是服務用戶的推論支出 | 支持 | 3.1、3.2（兩年倍數一致）、4.2 反向檢驗 |
| 126 億中約 6.5 億屬研究推論（列研發） | 部分支持 | 總額相容；分項無一手 |
| 84 億是服務推論的最佳點估計 | 部分支持 | 75／78／88 三源一致；但 75 是營業成本全額而非算力，84 在區間內偏上 |
| 現行區間 7.5–8.8 涵蓋合理範圍 | 不支持（低端） | 3.3：營業成本含非算力項，低端應約 6.0 |

方向檢核（第 10 條）：本題三個歧義的處理：(1) 把 Microsoft 端多出的部分歸為研究推論——**收窄**（排除 126 億作主值）；(2) 營收分成記帳位置未知時保留兩種讀法——**保留**；(3) 低端由 7.5 放寬到約 6.0——**保留／放寬**。收窄 1、保留 2。

涵蓋檢核（第 11 條）：[A] 會計恆等式（付 Microsoft 172 億橋接、營業成本拆分）已做；[I] 誘因（Zitron、OpenAI、Microsoft 三方）已做；[P] 物理面只記錄、非決定性（缺 OpenAI 2025 服務 GW 的獨立數字）。未做：Microsoft 對 OpenAI 的實際計價（牌價或成本加成）——已搜尋，未找到；營收分成在 OpenAI 帳上的位置——已搜尋，未找到。

## 6. 判斷

- **立場：同意維持 84 億為主口徑**（Agree）；126 億保留為對照列，標籤改為「Microsoft 端推論類工作負載（含研究推論）」。
- **把握：中。**
- **基準情境（約 65%）**：服務推論 7–8.5 億×10；m 約 0.41–0.48。**替代 A（約 25%）**：營收分成與非算力項在營業成本內，服務推論約 6；m 約 0.57。**替代 B（約 10%）**：部分服務推論列研發（新產品），服務推論 9–10；m 約 0.35–0.38。採 126 億（m 0.27）的情境機率很低（<5%，含於 B 的尾端）。
- **主要驅動**：(1) 營業成本中非算力項與營收分成的規模；(2) 研發付 Microsoft 10.59 中推論類工作負載的比例。
- **承重輸入**：F5（查核數，最強）；3.3 的扣除項全為 [Assumed]／[Analogy]，**放寬低端的結論主要依賴這些弱輸入**，所以只建議放寬區間，不建議移動主值。
- **最強反證與處理**：126 億是交易對手的權責帳。處理：總額與查核財報相容，差額只能落在研發；且 2024 年同倍數，OpenAI 當年已分列研究算力。
- **證偽條件**：(a) OpenAI 招股文件（若 IPO）或後續查核財報揭露營業成本中算力金額 ≥ 10；(b) 出現 Microsoft 推論 SKU 只含對外服務的說明；(c) 營收分成確認列在營業成本（會把主值往下推，不是往上）。
- **實務含義**：m 的主值不變（0.407）；m 區間高端應由約 0.46 放寬到約 0.57。這不改「未回本」的判讀方向（m 越高越接近回本，但仍取決於 L）。另外，126 億減服務推論約 6 的「研究推論」可作研發 GW（`L1_Ans1`–`Ans3`）的外部證據，屬交接檔第 3 節第 6 項（訓練支出），暫記錄。
