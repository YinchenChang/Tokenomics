## 1. 題目

### Q1（D3）2025 年 OpenAI 可用推論機隊的世代組合
- 對象：Hopper、GB200、GB300 各自的占比，以 2025 年平均或 2025 年底為準，兩者都要寫明。
- 現值是 60%／40%／0%，沒有來源。
- 線索：
  - 2025-10 前後 Azure 為 OpenAI 部署大規模 GB300 叢集（Microsoft 公開資料）。
  - CoreWeave、Oracle 的 GB200 交付時點。
  - OpenAI 與 NVIDIA、AMD 的協議。
- 產出：每個世代給低／基準／高三個值，並說明換算方式，例如由 GPU 數換成 MW 時用的單機功率。

### Q2（D5）實際服務吞吐量的獨立驗證點（非 MLPerf）
- 目標是每顆 GPU 每秒輸出的 token 數，最好帶有模型與 SLO 條件。
- 線索：
  - 雲端業者或模型商公布的生產吞吐，例如 DeepSeek 2025-02 的 H800 推論系統揭露。**模型已用它做 η_p 校準，所以只能當背景，不能當獨立驗證點。**
  - 第三方的 serving benchmark，例如 vLLM、SGLang 的公開測試，或 Artificial Analysis 的每 GPU 推估。
- 每個候選要註明能否與模型的哪一層級（Luna／Sol／Astra）、哪一世代對應。
- 另外整理 MLPerf Inference v6.0／v6.1 中 DeepSeek-R1、Llama 系列在 Hopper、GB200、GB300 上的結果，作為**上限檢查**的輸入。
  - 寫明輪次、提交類別（available／preview）與提交者。
  - 提交者是廠商時標 Interested-party。

### Q3（D5）RL rollout 與 harness 輪數的獨立對照目標
- 對象：公開的 RL 訓練中 rollout 算力占比，以及代理任務的平均輪數。
- 這兩項都要找與模型現有對照目標**不同**的來源。現有對照目標見稽核 3B 段 B04、B08。

### Q4（D6）Hopper 相對 GB300 的 decode 效率
- 用 MLPerf 中 Hopper（H100、H200）的結果，或 2025 年 Hopper 生產環境的實測，推出 η_d 倍數的獨立依據。
- 模型現值 1.5，是為了讓 Hopper 產出不變而倒推出來的。
- 產出：倍數區間，以及推導過程。

### Q5（D13）實際利用率
- 對象：推論機隊的平均 token 吞吐 ÷ 容量。現值 0.35，沒有來源。
- 注意口徑：這不是 SM 利用率，也不是 GPU 開機率。

### Q6（D16）Hopper 的設施與價格
- (a) 2023–2024 年 Hopper 氣冷資料中心的 PUE。
- (b) Hopper 機架或 8 卡伺服器在部署當時（2023–2024）的價格。
- 現在模型用的是液冷參數和 2026 年二手價。
