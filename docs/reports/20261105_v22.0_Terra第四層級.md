## 1. 本輪做了什麼、為什麼（白話）

B1、B2 已經把 Terra 放進所有計算頁，但它在付費組合裡的份額是 0，所以每個既有數字都沒變。本段（B3）把 Terra「打開」：

1. **組合改變**：2026 年付費 token 組合由 Luna 0.40／Sol 0.45／Astra 0.15 改為 Luna 0.40／**Sol 0.30**／Astra 0.15／**Terra 0.15**（J6：Terra 半價、性能接近 Sol，主要替代 Sol）。免費組合 Terra 仍是 0（免費方案沒有 Terra）。家族研發計入 Terra（`B4_TerraFam`＝1，J9）。這三格都用「只在仍為舊值時才寫」寫入 Excel。
2. **先把三項公式改成四項，再改組合**：`IF_TokGWPaidMix`（Interface N 節）與 `L1_TokGW_PaidCap_VR200`（L1 第 127 列）原本只加 Luna／Sol／Astra 三項，若不先改，Terra 的 0.15 份額會被靜默丟掉。`IF_PxEffMix` 讀 Cap_In 第 90 列，B2 已是四項。
3. **Terra 契約名稱**：Interface 新增 **R 節**（第 384–461 列，在所有既有列之下），66 個名稱（`IF_*_Terra` 52、`IFW_*_Terra_*` 14），每列寫明「對應 X 節」，口徑與 Luna／Sol／Astra 的同名列相同；L1 末端第 149–151 列加 `L1_CostDec_Terra_VR200`／`_GB300`、`L1_RevGW_Terra_VR200`（各含低／高）。不建 `CAP_Px25_Terra*`（2025 沒有 Terra）、`L1_RLshare_Terra*`、`L1_PretrainFLOP_Terra*`（J13）。區間端點 `RNG_IF_*_Terra_*` 28 個由 `tools/gen_ranges.py` 重產時自動加入。Terra 的「生產折減」名稱（`_Prod`）需要的鏡像計算，以第二次 X1 鏡像補在 `*_Prod` 頁（同位置、不動既有鏡像格）。
4. **Terra 牌價改連 SRC**：Cap_In F6:F8 與 F 節第 59 列 E:G 由藍字數值改為 `=SRC_PRC_066／067／068`（值同為 1.00／0.05／5.00），三筆 SRC 由 Alt 改 Active。

### 為什麼 `L1_M` 會上升？（不是變現改善）

`L1_M`＝實際營收 ÷（需求面付費 token × 有效牌價）。營收與需求面 token 是觀測值，本版沒有改；有效牌價因為 Sol 的 0.15 換成半價的 Terra 而下降 6.05%，所以 m 機械性上升 1 ÷ 0.9395 − 1＝**6.44%**。這只是同一筆營收換了一個比較便宜的「標價」來比，**不是 OpenAI 變得更會賺錢**。P×Q 裡的 P＝有效牌價 × m，兩者的乘積不變；所以 `L1_RevGW_PQ_VR200` 的變動完全來自 Q（每 GW 付費產能 +4.76%，Terra 每 GW 產能約為 Sol 的 1.6 倍）。下游讀 `L1_M` 做時間序列比較時，v22.0 以前與以後不可直接相比。
