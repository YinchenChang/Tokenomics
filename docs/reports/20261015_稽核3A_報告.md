## 1. 一句話結論

510 列沒有找到斷引用、欄位錯位或層級常數錯誤，公式都能被獨立重算出相同數值；問題集中在**成本與攤提的閉合與口徑**：由上而下攤提總額只閉合到訓練算力持有成本的 82–88%（因為快取命中只進成本、不進產能），自下而上「回本所需溢價」的分母含免費 token（Luna 分母是付費 token 的 7–8 倍），同一個 `_Prod`／`_Life` 名稱在 token 與營收、`IF_` 與 `IFW_` 之間用不同的折減方式（比值 0.49–0.81），而效率校準是「兩點解兩數」的恰好決定擬合，decode 有效 MFU 只有 1–2.5%，比 MLPerf 稽核結果低 30–51%。

## 2. 本部分的推導主幹（非工程語言）

1. **硬體與資料中心成本**：機架價格、網路、儲存 → IT 資本；土地、建物、電力、散熱 → 廠房資本；折舊或資本回收＋電費、維護、人員 → 每 GW 年持有成本（會計／經濟）→ 每 GPU 小時成本（DC_Cost → Interface 第 6–15 列）。
2. **效率校準**：InferenceX 兩個 GB300 實測點聯立，解出 decode 效率 η_d 3.58% 與每層延遲 161 µs；其他世代乘倍數（Calib）。
3. **每架產出**：規格 × 模型架構 × SLO × 校準效率 → 批次大小 B* → 每 GPU decode／prefill 速度 → 每架、每 GW 產出（Perf → `IF_TokGW_*`）。
4. **每 M token 成本**：每 GPU 小時成本 × 每 M token 所需 GPU 秒，再 ÷ 基準利用率 0.6（Unit_Cost → `IF_Cost*`）。
5. **快取儲存**：KV 大小 × 儲存層單價 × 保留時間 ÷ 命中次數（Cache_Store）。
6. **1 GW 參考機隊**：以 2025 OpenAI 支出比切成付費服務 0.22、免費服務 0.19、訓練＋研發 0.59 GW（Fleet_1GW）。
7. **訓練攤提**：自下而上＝研發計畫成本 ÷ 壽命內服務 token；由上而下＝訓練占比 ÷（1 − 訓練占比）× 服務成本；兩者之比為縮放倍數，下游預設（c）＝自下而上 × 縮放倍數（Amortize → `IF_Amort*`、`IF_FullCost*`）。
8. **介面瀑布**：每 GW 產能與營收 100% → × 利用率 → × 生產折減 → × L × m（Interface 第 233–286 列 → `IFW_*`）。
9. **批次推論**：同一套公式換成 20 tok/s 速度下限與 rollout 請求形狀，供訓練頁使用（Perf_Batch）。
