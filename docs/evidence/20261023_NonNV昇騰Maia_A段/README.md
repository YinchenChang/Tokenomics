## 1. 結論（先看這裡）

| 候選 | 每 GW 產出比（低／基準／高） | 每 GW 持有成本比（低／基準／高） | 每 token 成本比（基準） | 標記 |
|---|---|---|---|---|
| 華為昇騰 910C／CloudMatrix 384 | 0.05／**0.08**／0.15 | 0.45／**0.55**／0.70 | 約 6.9 倍 | Assumed |
| Microsoft Maia 200 | 0.25／**0.55**／0.75 | 0.40／**0.50**／0.60 | 約 0.9 倍 | Assumed |

白話：
- **昇騰 910C 約等於「Hopper 級」的每 GW 產出**（模型內 Hopper 為 0.10）。它單顆實測接近 H800，但每顆沒有 FP4、整機吃電約 559 kW（第三方估計），所以每 GW 能服務的 token 只有 VR200 的 1/12 左右。它的設備單價很低（整機約 $8.2M，折算每 kW 價格約為 VR200 的 0.4），因此持有成本比只降到 0.55，**每 token 成本仍約為 VR200 的 7 倍**。
- **Maia 200 的紙面算力密度不差**（每 kW 峰值算力約為 VR200 的 0.68），產出比的大小幾乎全由「軟體成熟度」決定，這是沒有任何第三方實測的參數，我用 0.45–1.0 的區間表示。價格完全沒有公開資料，持有比是自下而上的區間推估（查核後下修）。
- 兩列都維持 **Assumed**（與既有五列一致）。推導與證據已把每個輸入的出處與標記寫清楚，但外推成分大，不宜標為 Derived。

## 2. 推導方法（簡述；逐格在「推導」頁）

1. **產出比**＝候選每 GW 可服務 token ÷ VR200。模型內 decode 與 prefill 皆為「算力綁定」，所以用：
   `產出比 ＝（候選每 kW 峰值算力 ÷ VR200 每 kW 峰值算力）× 有效效率因子 f`。
   - f 不是自訂：我用模型現值**反推**既有世代（Hopper 0.74、GB300 0.90、GB200 1.04），所以 f 的區間 0.45–1.0 有模型內的落點。
2. **昇騰另加第二條路（實測錨定）**：模型 Hopper 產出比 × 每 kW 顆數比 × 每顆實測 token 比（華為論文與 DeepSeek 公開 H800 數字）。兩法的基準取平均、區間取包絡（0.0465–0.156）。**查核提醒：兩法同源**（都錨在模型 Hopper 還原值與同一 kW 密度比，只差乘數 0.76 對 1.0），平均不是獨立交叉驗證；基準 0.08 實質是「Hopper × 每 GW 顆數比 0.88 ×（0.76–1.0）」。
3. **持有比**＝`1 − s ×（1 − k）`。s＝0.77，是 VR200 持有成本中「隨 IT 設備資本支出成比例」的部分（折舊、維護、稅險與資金成本的 IT 份額）；k＝候選每 GW IT 設備資本支出 ÷ VR200 的 $37.59B。廠房、電費、人員不隨設備價格變。
4. 每個物理量（每顆峰值、功率、每 GW 顆數、單價、軟體折減）都列在推導頁並附證據編號；VR200 每 GW 291,744 顆，對照昇騰約 63.2 萬顆、Maia 約 69.0 萬顆。
5. 查核員用獨立程式回測持有比公式：對模型自己的 Hopper／GB200／GB300 得 0.793／0.721／0.890（模型 0.794／0.722／0.8905），公式在廠房成本相同的世代準確。

## 3. 敏感度（一次動一個參數；基準＝其餘不動）

**昇騰 910C**（基準產出比 0.080、持有比 0.533）

| 參數 | 變動 | 產出比 | 持有比 |
|---|---|---|---|
| 效率因子 f（方法一） | 0.5／0.74／1.0 | 0.047／0.069／0.093 | — |
| 整機功率 | 559→425 kW | 方法一 0.069→0.091 | 0.53→0.63（套數變多、資本支出變高） |
| 每顆實測 token 比（方法二） | 0.6／1.0／1.3 | 0.055／0.091／0.119 | — |
| 整機價格 | $6.0／8.2／12.0M | — | 0.45／0.53／0.68 |

功率口徑提醒（查核）：559 kW 搭配 SemiAnalysis 的 GB200＝145 kW，而模型分母的 GB200 為 132 kW；按模型口徑縮放（約 509 kW）基準產出比約 0.088，若取 The Register 轉述的約 600 kW 則約 0.075，所以基準 0.08 實際落在 0.075–0.09。

結論會翻轉的條件：若整機功率其實是 350–425 kW 而非 559 kW，且單顆表現同 DeepSeek 測得的上緣，產出比可到 0.15；若 DeepSeek 2025-02 自測的「約 H100 的 60%」才是真實，產出比降至 0.05。**最大不確定是 559 kW，它只有 SemiAnalysis 一個來源鏈。**

**Maia 200**（基準產出比 0.54、持有比 0.488）

| 參數 | 變動 | 產出比 | 持有比 |
|---|---|---|---|
| 效率因子 f | 0.45／0.80／1.0 | 0.30／0.54／0.68 | — |
| 機架功率 | 73.6／64／57.6 kW | 0.47／0.54／0.60 | — |
| 機架價格 | $0.5／0.8／1.2M | — | 0.39／0.49／0.62 |

「必須成立什麼」：產出比要到 0.75（高端），需要 f 約 1.0（效率≈GB200）**且**機架功率≤58 kW；要超過 0.75，單靠 Maia 的規格做不到（每 kW 峰值算力上限為 VR200 的 0.68–0.75）。微軟自述的「每瓦 token 為領先 GPU 的 1.7 倍」若基準是 GB300，會隱含 1.09，已超出此上限，我視為行銷口徑，不採用。

**交叉檢核（不進建議值）**：微軟稱 Maia 200「每美元效能比艦隊最新硬體高 30%」（基準未點名）。若基準是 GB300，Maia 的「產出÷持有」需達 0.97；本表基準 1.11（比值 1.14），**與自述相容**。微軟論文另寫「TCO 降 30%」（約 1.43× perf/$，據查核員），需求升至 1.07，本表基準仍略高於需求。自述的基準若是 Maia 100（CRN Asia 的讀法），這個檢核就不成立。價格下修前（$1.0M 基準）的比值是 1.006，下修後對自述更寬鬆，但這是價格由自下而上推算調整的結果，不是為了迎合自述。

## 4. 與既有五列（尤其 TPU v7、Trainium3）的相對位置

| 候選 | 產出比 基準 | 持有比 基準 | 每 token 成本比 |
|---|---|---|---|
| AMD MI455X | 0.7 | 0.9 | 1.29 |
| Google TPU v7 | 0.8 | 0.8 | 1.00 |
| AWS Trainium3 | 0.5 | 0.7 | 1.40 |
| Cerebras WSE-3 | 0.4 | 1.0 | 2.50 |

| **Microsoft Maia 200（提案）** | **0.55** | **0.50** | **0.9** |

- **Maia 200 位置合理**：單顆 FP8 5.07 PF（微軟）高於 TPU v7 的 4.6 PF、約為 Trainium3（2.52 PF）的 2 倍，功耗卻低（750 W），所以紙面上不弱於 TPU v7；但無第三方實測、量產僅數萬顆、軟體堆疊新，因此基準 0.55 落在 Trainium3（0.5）與 MI455X／TPU（0.7–0.8）之間。**限制**：TPU v7 與 Trainium3 的機架功率我都沒找到（E20），所以無法用同一套「每 kW」方法重現這兩列，只能做單顆規格層級的比較。
- **Maia 的持有比（0.50）低於 TPU（0.8）與 Trainium3（0.7）**：這是方法差異，不是證據差異。既有列沿用「持有比接近 1」的 Block 1 慣例；本提案依「候選每 kW 設備價遠低於 VR200」推導。若 Andy 偏好沿用慣例，改為 0.7–1.0（待判斷 Q3）。
- **昇騰是離群值（0.08 vs 既有最低 0.4）**：合理，因為其他列都是 2026 年 3nm／FP4／HBM3e–4 世代，而 910C 是 7nm、無 FP4、HBM2e，位置更接近模型內的 Hopper（0.10）。每 token 成本比 6.9 與模型內 Hopper（約 7.6）相近，與既有列相差一個量級，提醒下游（MAG、智譜）使用時要分清「現行主力」與「新世代」。
