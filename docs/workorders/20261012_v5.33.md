## 0. 起因

- v5.32 的 m 追蹤（Cap_In H 節；`L1_MImplied`）得到合併路線隱含 m＝**1.74（1.05–2.95）**，落在 Gov_Map 區間 0.3–1.0 之外（Checks M1 Warning，預期）。chat 端判斷（交接檔第 4 節，Andy 已讀）：m＝1 很可能高估（分母可靠的路線——API 0.85、程式代理 0.73、Anthropic 用量營收——都在 1 以下），合併 m > 1 的主因是**分母（付費 token 數）偏低**，而且集中在 ChatGPT。
- 現行付費 token 分母（Alloc A 節，2025 基準年，M tok／年）：
  | 項目 | 公式 | 數值 | 輸入與標記 |
  |---|---|---|---|
  | ChatGPT token | 每日提示數 × 每則 token × 365 | 3.65 × 10⁹ | `SRC_DEM_012` 2.5 B 則／日（2025-07，利害關係方）× Alloc_In C15 每則 4,000 tok（Assumed，2,000–6,400；備註「上限無直接來源，Q1 最弱輸入」） |
  | ChatGPT 付費 token | × (1 − 免費占比) | 1.46 × 10⁹ | Alloc_In C16 免費占比 0.6（Assumed，0.4–0.8） |
  | API token | B tok/min × 525,600 × 全年平均比例 | 2.37 × 10⁹ | `SRC_DEM_010` 6 B tok/min（2025-10）× Alloc_In C14 0.75（Assumed，0.6–0.9） |
  | 付費 D 合計 | | **3.83 × 10⁹**（≈10.5 T tok／日） | 合併 m 分母；混合有效單價 1.9607 $/M（Cap_In H4） |
- 分母已知的三個口徑缺口（交接檔第 4 節）：(1) 每則 4,000 tok 未含對話歷史（Decisions C4：整段對話的每任務指標約 ×2–2.5）、工具內容與推理 token；(2) 付費占比以**人數**切（付費 59 M ÷ 週活 8–10 億 ≈ 6–7%，卻設 token 占比 40%），沒有用量分布依據（`SRC_DEM_045`：Enterprise 員工訊息 p95 ÷ 中位數＝6）；(3) 訂閱營收含圖像、語音、影片、Deep Research 等非文字服務與低用量企業席次，這部分讓訂閱路線的 m 看似 > 1，不是 token 問題。
- 「必須為真」的框架（本單 A 段要回答的核心）：以 2025 毛額營收 13.07 $B 與單價 1.96 $/M 計，m＝1 需付費 token＝6.7 × 10¹⁵（現值 × 1.74）；m＝0.6 需 11.1 × 10¹⁵（× 2.9）；m＝0.3 需 22.2 × 10¹⁵（× 5.8）。物理面（`L1_GapPrompt` 2，1–3.2）只支持 token 低估約 1.3–2 倍，不是 10 倍。所以 A 段要同時校準分母的**下限（需求路線能算出多少）**與**上限（物理產能最多能供多少）**，並把非 token 的分子因素拆出來，才能說 m 高估到什麼程度。
- 第一原理三類（候選框架，本單四項的歸屬）：[A] 會計恆等式——第 1、2 項（token＝則數 × 每則 token × 付費占比）、第 4 項（營收＝文字 token 營收＋非文字營收）；[P] 物理守恆——第 3 項（帳單 → GW → token 產能上限）；[I] 誘因／資訊——每項的來源立場（OpenAI 融資期間有呈現成長的誘因；OpenRouter 樣本偏 API 與代理流量）。

## 1. A 段查證項目

資料紀律同 v5.31／v5.32：每筆數值、單位、期間、來源、日期、標記（Verified／Interested-party／Analogy／Assumed／Derived）；SemiAnalysis 不可單獨引用；同一底層來源的轉載不算獨立；利害關係方標明誘因。**「找不到」與「不存在」分開寫**：每個缺口列出實際搜尋過的來源與關鍵字；找不到時寫「未找到」並給方向性代理值與其差異，不得用代理值默默取代。Analogy 與 Assumed 一律給區間，不給點估計。

### 1.2 付費用量占比：改以訊息或 token 切分
- 現值 Alloc_In C16「ChatGPT token 中免費用戶占比」0.6（Assumed），等於付費 token 占比 0.4；但可查的人數口徑只有約 6–7%（付費 50 M＋9 M ÷ 週活 8–10 億）。要建立四個口徑並列：
  | 口徑 | 現有依據 | 要補的證據 |
  |---|---|---|
  | 人數 | `SRC_DEM_019`／`020`（59 M）÷ 週活（待登錄） | 週活用戶時間序列（2025-07、2025-10、2026-02） |
  | 訊息數 | 無 | 付費用戶占 ChatGPT 訊息比例：OpenAI／NBER 使用論文是否按方案（Free／Plus／Pro）分訊息量；OpenAI 任何「付費用戶每日訊息」揭露 |
  | token | 無 | 付費用戶每則 token 是否高於免費（思考模型、長上下文、工具為付費方案功能）；方案限流（Plus／Pro 每 3 小時或每週上限）作為每付費用戶用量**上限** |
  | 推論支出 | `IF_FreeShare` 0.46（`SRC_DEM_005` ÷ `004`，支出口徑） | 支出占比 → token 占比的換算假設（免費層用較低層級模型、較低單價） |
- 分布證據：`SRC_DEM_045`（p95 ÷ 中位數＝6）之外，找消費端的用量分布（重度用戶占比）；若只有企業端資料，標 Analogy 並說明消費端差異方向。
- **已知缺口**：付費用戶占 ChatGPT 訊息比例。未找到時，以「人數占比 × 付費／免費每人用量倍數」推導，倍數給區間並標 Assumed，列出使倍數成立所需的每付費用戶每日訊息數，與方案限流對照是否可行。
- 低用量企業席次（`SRC_DEM_030` 7 M 席次；Enterprise 分布）在本項處理：席次付費但用量低，使訂閱路線「每付費用戶 token」的平均值被拉低、m 被拉高；與 1.4 的非文字服務分開，不重複扣。

### 1.3 物理上限：推論帳單 → 服務 GW → token 產能
- 目的：給需求路線（1.1 × 1.2）一個不可超過的天花板，並反向得出「分母最多能放大幾倍」。
- 路線 A（支出路線）：`SRC_DEM_018` 12.6 $B（12.3–13.0，Azure 計價）÷ Azure 計價對持有成本倍數（Alloc_In C23，2，1.5–3）÷ 世代組合持有成本（Alloc B 節第 30 列）＝服務 GW；× 每 GW 年產能（Alloc 第 22–25 列，付費與免費分列，注意該列已含 `IF_Util` 0.6）× 實際利用率修正（Alloc_In C24 0.35 ÷（`IF_Util` × `CTL_ProdDerate`））＝年 token 產能上限。
- 路線 B（算力揭露路線）：`SRC_DEM_008`／`009`（0.6 → 1.9 GW，口徑未明）取 2025 期間平均，扣訓練占比（Alloc 第 55 列 0.588，支出口徑）得推論 GW，同上換算 token；GW 口徑（IT／設施）未明者依 CLAUDE.md 第 7 節逐一標註並給兩種讀法。
- 兩條路線各給低／基準／高；與 `SRC_DEM_013`（Epoch 10–100 T／日）、Alloc 第 12 列現值 16.5 T／日、以及 1.1 × 1.2 重算的需求並列成一張表。結論要回答：(i) 重算需求是否落在天花板之下；(ii) 若天花板低於 m＝1 所需的 6.7 × 10¹⁵，則 token 數不可能解釋全部缺口，剩餘要由分子（1.4）或 m 本身承擔——這是本單最重要的交叉檢查。
- 不改 `L1_ScaleServe`、`L1_GapProduct` 的定義；本項只是用同一組輸入另算一個「token 上限」。

### 1.4 對照項：訂閱營收中非文字服務的份額
- 把訂閱營收（Cap_In H1：13.07 × 0.70，低端 0.612、高端 0.82）拆成：文字 token 服務、圖像生成、語音、影片（Sora）、Deep Research／代理（長任務，token 密集但屬文字）、其他；各給份額區間與標記。候選來源：OpenAI／NBER 使用論文的訊息類型分布（若有圖像／語音類別）、OpenAI 圖像生成與 Sora 的用量公告、方案功能頁、第三方量測。
- 扣法：只從**訂閱路線的分子**扣除非文字服務份額（圖像、語音、影片），Deep Research／代理不扣（它是文字 token，分母該算進去而不是分子扣掉）；重算訂閱 m 與合併 m，給扣除前後對照。API 路線不扣（API 營收已按 token 計價）。
- **已知缺口**：OpenAI 未揭露訂閱營收按功能的拆分。未找到時給 Assumed 區間，並列出「要讓訂閱 m 降到 1 以下，非文字份額至少要多少」的反推值，與區間比較是否可行。
- 訂閱占比基準（待決：0.70 現值 vs 0.765 A 段試算副本）：A 段用 0.70 計算，0.765 作敏感度列，不替 Andy 決定。
