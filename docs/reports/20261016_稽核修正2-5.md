## 8. 待 Project 判斷

1. **`IFW_TokGW_*_Life` 不建 LifeSelf**：產能名稱不受 L、m 影響，只建營收 8 個名稱；工作單文字未明列，保留現狀。
2. **B24、B25 當比較列**：它們是兩個數字相互比較，不是對外部量測的驗證，未計入驗證項。
3. **V2 的 v5.1 來源輪次**：GB200 用 v5.1，而軟體已更新到 v6.x，v5.1 比值 1.44 是否作為上限使用，需判斷。
4. **V7、V8 LMSYS 條件**：LMSYS 的服務條件與模型規模與本模型不同，比值 0.05–0.07，請判斷是否仍保留 0.5–2.0 通過帶，或改為只作參考。
5. **V9、V10 RL 帶邊緣**：0.38／0.37 略高於 0.3；帶 0.1–0.3 的上限是 chat 端 J2 決定，我不改。
6. **M1–M4 與 L1 外部對照是否算驗證**：這些外部對照能否失敗？目前只收 D5 工作單列出的項目。
7. **判準儲存格未登錄 Gov_Map**：Checks V 節 H／I 兩欄的通過帶為黑字常數（工作單 J2 決定「黑字，不登錄 Gov_Map」），日後若要追蹤來源需另決定。
8. **W1 +5**：新增 5 筆利害關係方 SRC 無第二來源，GOV_Warnings 271 → 276，需判斷是否補第二來源。
9. **v5.1 server TPOT 假設 80 ms**：v5.1 伺服器情境的每用戶速度下限以 1000 ÷ 80 ms＝12.5 tok/s 計，80 ms 為假設，請確認。
10. **Hopper 用 H200 還是 H100 規格**：MLPerf v5.1 的 Hopper 實測為 H200，模型為 H100 規格；V1 比值含此差異。
11. **性質欄 U 欄的理由是 CC 依 2-4 報告與公式讀取後分類**：若 Project 對個別列有不同看法，請指出，逐列修正。
