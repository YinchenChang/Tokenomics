## Q1：Fairwater

### Microsoft
- **Microsoft Source〈From Wisconsin to Atlanta…AI superfactory〉（2025-11-12）。** Fairwater 網路用來支援 OpenAI、MAI 超級智慧團隊、Copilot 與其他領先的 AI 工作負載；Atlanta 於 2025-10 開始運作；GPU「hundreds of thousands」；沒有 MW 與分配比例。
- **AP（經 Yahoo Finance，2025-11-12）。** Microsoft 表示 Atlanta 的晶片將支援 Microsoft 自家、OpenAI 與其他 AI 開發者；無比例。
- **Nadella，Dwarkesh Podcast（2025-11）。** 「We didn't want to just be a hoster」（單一公司託管商）；把 Fairwater 2 描述為可在訓練、資料生成、推論間調度的機隊；GPT 系列的算力與 MAI 的算力分開談，沒有數字。
- **Hood，FY26 Q2 法說（2026-01-28；roic.ai 轉載）。** 新 GPU 的順序：先滿足 M365 Copilot 與 GitHub Copilot 等第一方，再給 R&D 與產品創新，其餘給 Azure；若 Q1、Q2 上線的 GPU 全給 Azure，Azure 成長會逾 40%。分析師問 Fairwater Atlanta 與 Wisconsin 時，她答多年期交付、不聚焦特定地點。OpenAI 約占商業 RPO 45%（轉載逐字稿，二手）。
- **Nadella，FY26 Q3 法說（2026-04-29；roic.ai 轉載）。** Wisconsin Fairwater 本月上線，比預定早約六週，因此能「recognize revenue earlier」；未說是哪類客戶的營收。Hood 未提 Fairwater；說第一方與 Azure 需求的拉鋸會持續。r1 註：提前認列營收只能說明有外部付費客戶，不能分辨是 OpenAI 還是 Anthropic 等。
- **Microsoft Source（2026-06-23）。** Mount Pleasant 第一棟完工並全面運轉；4 月已上電啟動；未載使用者；第二棟 2028 年完工。
- **Microsoft FY26 Q4 法說逐字稿（microsoft.com docx，2026-07-29）。** 當季新增約 1 GW；Maia 200 同時支援 OpenAI 與 MAI 模型；逐字稿沒有 Fairwater 與超級智慧團隊字樣，也沒有容量分配。Hood：需求持續超過供給；RPO 6,780 億，排除 OpenAI 成長 25%。
- **Microsoft AI〈Frontier Pre-training at Microsoft AI〉（2026-10-15）。** MAI-Base-2 預訓練用 16k GB200、38 天、2026 年 8–9 月；未載站點；MAI 算力「ramping quickly」但無總量。前一代 MAI-Base-1 用 8,192 顆 GB200（Crypto Briefing 轉述）。
- **Suleyman〈The Exponential Compute Ramp〉（2026-04-08）。** 談 Maia 200 與擴展趨勢；未提 Fairwater、未給 Microsoft GPU 數或 OpenAI 份額。

## Q2：token 帳需求面

### API 每分鐘 token
- **OpenAI〈Accelerating the next phase of AI〉（2026-03-31）。** 「more than 15 billion tokens per minute」；Codex 週活逾 200 萬、三個月 5 倍；ChatGPT 週活逾 9 億。
- **OpenAI〈The next phase of enterprise AI〉（2026-04-08）。** API 每分鐘逾 150 億（同值）；Codex 週活 300 萬；企業逾營收四成。
- **Exponential View（2026-04-06）。** 轉述 6B（2025-10）→ 15B（2026-04）。
- DevDay 2026（09-29；nocode.mba、CometAPI 摘述）：只公布 API 生成快 6 倍、Codex 快 8 倍；**無 token 量**。

### Codex
- **arXiv 2606.26959〈The Shift to Agentic AI: Evidence from Codex〉（2026-06-25；作者多為 OpenAI 員工，兩位學者為 OpenAI 付費顧問）。** 截至 2026-06-11 前 28 天窗口（非單日時點），Codex 占（Codex＋ChatGPT）輸出 token：OpenAI 員工 99.8%、組織用戶 63.3%、個人用戶 16.5%。圖說定義為 Codex 輸出 token 占兩者合計的比例（讀作彙總比，論文未明說）。個人用戶含 Free、Go、Plus、Pro。Codex 週活 1–6 月逾五倍。無絕對 token 量；未提 API。
- **OpenAI Help Center〈Codex rate card〉。** ChatGPT 方案的 Codex 自 2026-04-02 起按 token 類型計 credit，「priced based on API token usage」；說明頁只提到 API 存取與用自有 API key 的 Codex 不受模型退役影響，未直接寫計費方式。→ 推論：ChatGPT 登入的 Codex 不在 api.openai.com 的每分鐘 token 內。
- **WorkOS 部落格。** 方案額度與 credit 走 chatgpt.com 端點，API key 走 api.openai.com；並引 OpenAI FAQ 稱用 API key 的額外任務按標準 API 費率計費（第三方轉述，r1 改歸此處）。
- **Fortune（2026-03-04）。** Codex 週活逾 160 萬；自 2 月初每週處理 token 增 5 倍。
- **Codex 週活序列（OpenAI，經 gradually.ai 彙整）。** 03-31 逾 200 萬 → 04 初逾 300 萬 → 04-21 逾 400 萬 → 06-02 逾 500 萬；07-21 Codex＋ChatGPT Work 1,000 萬（Bloomberg）；08 月 Sottiaux 稱 2,000 萬、2,500 萬（定義不明）。
- **DigitalToday（OpenAI Enterprise Signal，2026-08-13）。** 企業客戶輸出 token 64% 來自 Codex；無絕對量。
- **Bloomberg（2026-07-31）。** Codex 占 OpenAI 內部週輸出 token 99.8%（內部，非對外）。
