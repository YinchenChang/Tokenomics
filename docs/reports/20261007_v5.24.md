## 五、CI paths-ignore：依據與驗證
**依據**（GitHub Docs「Workflow syntax for GitHub Actions」→ `on.<push|pull_request>.<paths|paths-ignore>`，2026-10-07 查閱）：
1. 「When all the path names match patterns in `paths-ignore`, the workflow will not run.」——推送的全部變更檔都落在清單內才跳過；只要有一個檔不在清單（例如 `model/`、`builder/`、`.github/`），就照常執行。
2. 「If you define both `branches`/`branches-ignore` and `paths`/`paths-ignore`, the workflow will only run when both filters are satisfied.」——與既有 `branches-ignore: [ci-status]` 是「且」的關係：`ci-status` 分支仍不觸發；其他分支在「不是全為文件」時觸發。
3. 「Path filters are not evaluated for pushes of tags.」——推標籤時不看路徑篩選，既有 `tags: ["**"]` 照常觸發（v5.22 加 `tags` 的目的不受影響）。
4. 比較口徑：既有分支的 push 以前後兩個 SHA 做 two-dot diff；新分支以「推送中最深提交的祖先的父提交」比較。單次推送超過 1,000 個提交時一律執行。
5. `pull_request` 未加 paths-ignore：合併門檻 job `parity` 仍在每個 PR 上出現（包括只改文件的 PR）。
