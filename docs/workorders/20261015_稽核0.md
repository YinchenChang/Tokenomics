## 1. 檢查項目（每完成一項：更新進度檔 → commit → push）

### C1 輸入治理完整性（以 Gov_Map 為準）

對 Gov_Map 每一列（GM_ID），以及全簿所有藍字輸入格，檢查以下各項：

1. 藍字輸入格是否都在 Gov_Map 有登錄；反過來，Gov_Map 的每一列是否都指向一格實際存在的輸入格。
2. 是否有 SRC_ID 或決策 ID。兩者都是「—」的，要列出。
3. 標記為 Analogy 或 Assumed 的格，是否有低值與高值。有沒有標記是 Verified 卻沒有 SRC_ID 的。
4. 目前值是否落在低值與高值之間。
5. 來源日期：從 SRC_* 與 SRC_Index 取得文件日期。距 2026-10-15 超過 6 個月、超過 12 個月、沒有日期，三類分開列。
6. 每一格輸入被多少個公式格直接引用。被引用 0 次的輸入要列出。

### C2 證據積壓

DB_Evidence 中，凡是符合以下任一條件的列，都要列出（含 ID、日期、主張摘要、對應參數、狀態、相關 SRC_ID）：

- 狀態是「待判定」或「待 Andy」。
- 判定是「待查」。
- 日期晚於相關 SRC 現行值的文件日期，但判定不是「採納」。

另外統計：上述各類的數量，以及每一列積壓了幾天。

### C3 依賴關係與瘦身盤點

建立全簿的儲存格依賴關係，含具名範圍、跨頁引用、範圍引用。公式中若用到 OFFSET、INDIRECT 等動態引用，列出所在位置，並以保守方式處理（把它可能引用到的整個範圍都算進去）。

**根節點**：
- 下游契約 `docs/plan/Tokenomics_downstream_contract.md` 所列的名稱
- 所有 `IF_*`、`L1_*` 具名範圍
- Checks 頁
- 所有 `GOV_*` 名稱

把每一個公式格與輸入格歸入以下其中一類：

| 類 | 定義 |
|---|---|
| 核心 | 可由根節點往上游追到，而且不在敏感度頁或鏡像頁 |
| 敏感度 | 位於 Sens_* 或 Sensitivity 頁 |
| 鏡像 | 位於 *_Prod 頁 |
| 治理與來源 | 位於 Gov_Map、Decisions、SRC_*、DB_Evidence、Checks、Load_Bearing |
| 死格 | 從任何根節點往上游都追不到的公式格或輸入格（不含純標籤文字） |

產出內容：
- 每頁各類的格數。
- 死格清單：頁、格、列標籤、公式。
- 瘦身估計：死格與鏡像、敏感度分別占全簿公式格的比例。
- 「核心推導列」清單，供第 3 段使用，以「頁＋列」為單位。

### C4 鏡像一致性

每一個 `*_Prod` 頁與它的核心頁，例如 Perf_Prod 對 Perf：

- 把公式轉成相對位置的寫法（R1C1）後逐格比對。
- 列出公式結構不同的格。
- 依各頁說明欄，確認除了「生產折減」等明訂的差異之外，沒有其他差異。

Sens_* 頁做同樣的比對：除了情境輸入格之外，公式結構應與核心頁相同。

### C5 公式內寫死的常數

在核心公式中，找出除了 0、1、2、100、1000、1e3、1e6、1e9、1e12、24、365、8760、3600 以外的數字常數。逐格列出：頁、格、列標籤、常數、公式片段。

（CLAUDE.md 第 6 節：不得硬編碼參數。Excel 內寫死的常數也是可疑項目。）

### C6 單位與標籤

1. 有單位欄的頁，輸入格的單位欄是空白的，列出來。
2. 同一個物理量在不同頁的單位不同，列出供人工判讀。例如以列標籤關鍵詞比對：「每 GPU」對「每架」、「$/M」對「$/k」、「GW」對「MW」、「年」對「月」。這一項只標可疑，不判斷對錯。

### C7 為第 1、2 段備清單

1. **第 1 段輸入清單**：每一格輸入一列，欄位包括：
   - GM_ID、頁、格、列標籤、單位、目前值、標記、低、高
   - SRC_ID、來源日期、被引用次數
   - 是否在 m 路徑上
   - 所在頁是否有世代維度（同一列在多個世代欄有不同值，或有世代欄頭）
   - 空白判讀欄：「代表什麼物件」「時點」「應否隨世代或時間變化」「口徑是否與使用它的公式一致」，留給第 1 段填寫
2. **m 路徑**：
   - 以 m 相關的名稱為根，例如 `CTL_Monetize`、v5.36 新增的計價倍數與 κ、L1 中與需求端和機隊端閉合有關的列（以名稱或標籤含「變現」「Monetize」「閉合」「缺口」等詞搜尋）。根的清單請在報告中列出。
   - 往上游追所有輸入格與核心公式列，產出 m 路徑清單，供第 2 段使用。
