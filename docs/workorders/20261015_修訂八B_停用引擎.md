# 工作單：修訂八-B 停用公式引擎與 parity，改由 LibreOffice 單一計算器檢查（工程類，2026-10-15）

- 分支：`claude/parity-rev8`（已有量測報告 `docs/reports/20261015_parity瓶頸量測與修訂八草案.md`）
- 預估：1–1.5 小時；單一代理；模型 Sonnet。超過 3 小時即停下（第 4b 節第 5 項），更新進度檔後結束。
- Andy 決定（2026-10-15 06:20）：網站短期暫停；同意以「修訂八-B」取代原修訂八草案；暫不做「推導鏈閱讀版」。
- 不改 Excel、不改 builder、不改任何數值。

## 背景（一句話）
全套 parity 約 170 分鐘，原因是 pycel 引擎每次重建約 100 秒、全套重建約 81 次。網站停用後，引擎只剩「與 LibreOffice 對答案」一個用途，因此整個停用；所有檢查改讀 LibreOffice 重算後的值。

## 1. 新的檢查架構（`tests/parity/`，資料夾名稱不改）

1. `conftest.py`：
   - 模型路徑：`engine` 不再匯入。改為自行讀 `model/CURRENT`；若設環境變數 `TOKENOMICS_MODEL` 則改用該路徑（供第 4 節故意改錯檢查）。
   - session fixture `lo`：提供 `lo.view(inputs: dict)`。對每組輸入：`parity_lib.set_inputs` → `lo_recalc` → `openpyxl.load_workbook(data_only=True)`，只保留「全部非空儲存格值」的 dict 後關閉活頁簿。以輸入內容為鍵快取，同一組輸入整個 session 只算一次。`inputs={}` 即基準。
   - session 開始時，以 2 條執行緒並行，把 `scenarios.yaml` 的全部情境與基準預先算好（實測 26 情境 187 秒）。
   - `View` 物件提供與舊 `Engine` 相同的唯讀介面：`get(sheet, ref)`（單格純量；範圍回巢狀 list）、`get_name(name)`（規則同舊 `Engine.get_name`：單列或單欄攤平成一維 list）、`names`、`formula_cells`、`evaluate_all()`（回傳全部公式格值 dict）、`name_ref(name)`。具名範圍與公式格清單從原檔（公式模式）讀一次。空格一律回傳 `""`（同舊 `norm`）。
   - 不再需要 `set_key`：要改輸入的測試改成呼叫 `lo.view({...})`；輸入鍵格式沿用 `resolve_key`（從 `engine/core.py` 移入 `parity_lib.py`，原樣搬移）。
2. `test_parity.py` 改寫：
   - 刪除：`test_scenario_parity` 的「引擎 vs LibreOffice」比對、`test_cache_matches_fresh`、`cache_path`、`test_scenarios_actually_change_outputs`、`test_incremental_recalc_matches_fresh_and_is_fast`、`test_full_recalc_time`、`new_engine`、`_clone`、`base_engine`、`template_engine`、`FRESH_STATE`、重算秒數警告相關常數與類別。
   - 新增 `test_scenario_checks`（依情境 parametrize）：該情境全部公式格錯誤值 0；非基準情境相對基準至少改變一個公式格（防空轉）；原 `test_scenario_parity` 內 `h_alloc_*`、`h_prod_derate_070` 的專屬斷言原樣保留（改讀 `View`）；`results_store` 寫入改變格數、其中 Interface 格數、錯誤值格數。
   - 其餘期望值測試：`new_engine(model)` → `lo.view({})`；`_clone(...)` ＋ `set_key` ＋ `evaluate_all()` → `lo.view({鍵: 值, ...})`。**斷言與容差一律不改。** 若某斷言因 LibreOffice 存檔只有 15 位有效數字而失敗（舊斷言以全精度精確相等比對），只在該斷言加上相對 1e-12 的容差，並逐項列入報告表 1；不得改期望值。
   - `test_named_ranges_vs_libreoffice`：改用原檔 `openpyxl` 讀到的名稱，不建引擎。
3. `test_functions.py`（pycel 與 LibreOffice 的函數語意比對）：移到 `tests/legacy/`。
4. `test_ci_status.py` 照常保留並通過；若因 CI job 名稱改變而需調整 fixture，只做最小修改。
