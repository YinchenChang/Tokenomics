## 1. 工作項目

### S1 推導鏈地圖（先做）

從 m 相關的根往上游追，畫出主幹。根的清單見第 0 段報告；`CTL_Monetize`、`L1_M*`、`L1_Gap*`、`L1_ScaleServe`、`AL_Kappa`、`AL_SpendBasis`、`L1_LReqFleet`、`L1_PriceReal*` 等都包含在內。

主幹的寫法：用非工程語言，從需求端（提示數 × 每提示 token × 單價 → 營收）與機隊端（GW → token 產能 → 可收費 token）兩側各寫一條，標出它們在哪裡相交、用什麼恆等式閉合。每一步要寫明「頁＋列」與具名範圍。

產出：報告第 2 節（約 1 頁），明細的「推導鏈」頁。

### S2 逐列邏輯檢查

對 561 個頁＋列逐列檢查。同一列跨世代或層級欄的公式結構相同時，讀一次即可，但要抽查各欄的引用是否對位。每一列檢查以下各項，有問題就標代號：

| 代號 | 檢查 |
|---|---|
| L1 | **量綱**：分子、分母的單位相乘除後，是否等於該列標示的單位（token、$、$/M、GW、MW、年、GPU 小時、每 GPU 對每架、IT 對設施） |
| L2 | **口徑一致**：相加或相比的兩個量是否同口徑（輸入對輸出 token、思考是否計入、付費對全部、支出對 token、名目對實質、同一年度、同一層級） |
| L3 | **引用對位**：世代、層級、情境欄是否引用到正確的對應欄（例如 VR200 欄有沒有誤引 GB300 欄），INDEX 的欄號是否正確 |
| L4 | **重複計算或漏算**：同一個效應（利用率、折減、L、m、快取命中、免費占比）有沒有在鏈上被乘了兩次，或在該乘的地方沒乘 |
| L5 | **閉合恆等式**：缺口恆等式（`L1_Gap*`）的各項加總是否等於總缺口；有沒有某一項其實是殘差（倒算），卻被當作獨立估計呈現 |
| L6 | **循環或倒推**：m、L、κ、計價倍數中，有沒有哪一個是由想要閉合的目標倒推出來的。CLAUDE.md 與使用者原則都禁止用目標反推參數；這裡只標出來，不判斷 |
| L7 | **條件分支**：IF 的判斷條件與文字回傳值（例如「SLO 不可達」）在下游會不會被當成 0 或被忽略 |
| L8 | **與第 1 段 Y1–Y9 的連結**：這一列是否把 Y1–Y9 的問題傳到 m；傳遞的方式是乘數、加數還是倒算 |

### S3 傳遞強度（定量；只讀，不改檔）

針對第 1 段嚴重度「高」、而且在 m 路徑上的輸入（約 93 格；同一列合併計算），估計它對 `CTL_Monetize` 或 `L1_MImplied`、`L1_MFleet`、`L1_Gap*` 的影響方向與大小。

方法：
- 優先讀工作簿現有的敏感度頁（Sensitivity、Sens_*、Load_Bearing）。
- 沒有現成結果的，可以把公式鏈抽出來，在 Python 裡用「單一輸入 ±（區間端點）、其他不變」重算該條鏈。只能用工作簿的公式與數值，不得新增任何機制。
- 做不到的，寫「無法定量」並說明缺什麼。
- 若有 LibreOffice，也可以把工作簿複製到 `docs/evidence/20261015_稽核2/`（不碰 `model/`），改一格後以 headless 重算來量測。命令超過 2 分鐘就背景執行。

產出：一張表，欄位為輸入、所屬 Y 類、端點、m 指標的變化（%）、閉合缺口的變化。依影響大小排序。
