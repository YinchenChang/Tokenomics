## 3. κ 與實際流量形狀（A2＋chat 端計算）

### 3.1 更正：κ 的兩個值不是「權重方式」不同
- v5.36A（1.035）與 v14.3（0.852）用的是**同一種彙總法**：需求 token 加權的調和平均＝Σw ÷ Σ(w÷κ_i)，數學上等於 GW 加權的算術平均（chat 端驗證：兩式皆得 0.852）。
- 差距拆解：v5.36A 的各類 κ_i 配 v15.1 的需求權重得 0.931 → 權重效果（API 需求占比約 0.55 → 0.39）約 −0.10；各類 κ_i 的 GPU 秒校準改變（Sens_Perf 現值）約 −0.08。
- 交接檔與計畫檔「κ 的權重方式（GW 權重 vs 需求 token 權重）」這一題因此**取消**，改為「各類流量的形狀與 token 占比」，與 ISL／OSL 合併。

### 3.4 結構問題（列待 Project 判斷，B5）
κ 以「總 token（含快取輸入）」計，乘在機隊 token 上；但 m 的單價是參考請求（χ 0.55）的固定混合價。agent 型流量的 token 多半是快取輸入（牌價約新鮮輸入的 1/10），κ 上升時每 token 實價同步下降，模型只反映前者，會**高估機隊 token、低估 m**。2025 年 agent 流量比重遠小於 2026，影響有限；但 2026 欄與下游會放大。建議另立一版處理（價格端改用同一流量形狀的混合價），本 B 段不動。
