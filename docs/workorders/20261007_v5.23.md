## 3. CI 穩定性（工程類）

依據：master 合併 PR #23 後的 push run 189（`a5931f0`）失敗。`ci-status` 紀錄顯示：scenarios 第 4 片在「安裝 LibreOffice Calc」步驟中，`libreoffice-core`（43 MB）自 azure.archive.ubuntu.com 下載耗時約 19 分鐘，job 在 30 分鐘逾時被取消，`parity` 因情境覆蓋缺 4 個情境而失敗。其他 job 全部通過；與內容無關。

1. **LibreOffice 安裝**（scenarios 與 structure-recalc 兩處）：
   - 改為 `apt-get install -y -q --no-install-recommends libreoffice-calc`（原本連帶安裝 gstreamer 等推薦套件）。若缺少 headless 重算所需套件（例如 `python3-uno`、字型），只補必要者，並在報告列出最終套件清單。
   - 加上 apt 重試與逾時：`-o Acquire::Retries=3 -o Acquire::http::Timeout=30`（`apt-get update` 與 `install` 都加）。
   - 安裝步驟設 `timeout-minutes`（建議 10），失敗時整個安裝步驟重試一次（以 shell 迴圈實作即可，不引入第三方 action）。
   - 驗收：parity 全部情境不符 0，與 v5.22 相同；報告列出各 shard 的安裝秒數（取自 `ci-status` 或 step summary），與 v5.22 run 185／186 比較。
2. **`ci-status` 記錄各 job 的完整 Python 版本**：在 `jobs` 每一筆加 `python` 欄（例 `3.11.16`）。做法由 CC 決定（例如各 job 已寫的 `_results_*.json` 或 junit 加一個欄位，再由 `tools/ci_status.py` 讀取）；不得改變任何測試的斷言。目的：觀察 v5.22 快取指紋修正是否在「同一 run 內修訂號不同」時生效。`tests/parity/test_ci_status.py` 補對應測試。
3. **Node.js 20 淘汰警告**：把 `actions/checkout`、`actions/setup-python`、`actions/upload-artifact`、`actions/download-artifact` 升到以 Node.js 24 為目標的主版本。CC 先確認各 action 目前的主版本與破壞性變更（特別是 `download-artifact` 的 `pattern`／路徑行為）；若任一升級會改變 `parity` job 的情境覆蓋彙總或 artifact 路徑，該 action 維持原版本，並在報告說明。
- 以上三項不改 `model/`，不影響任何數值；合併門檻仍為 job `parity`，名稱、needs、斷言不變。
