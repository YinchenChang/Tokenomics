## 1. 一句話結論

q 是「同一個模型、同一個服務門檻、換新硬體」的產出比，所以它只能配「同等能力 token 價格」；但這一口徑的實證價格每年掉約 13 倍（約 −92%／年，且含演算法進步與競價，不只是硬體），遠低於讓世代每 MW 收入持平所需的價格變化率（約 −32% 到 −60%／年），不能直接乘 q；層級牌價（OpenAI／Anthropic／Google 各層級上市價）則多半落在門檻之上，算力租賃價則因 GB300、VR200 沒有公開標價而只能算 Hopper→GB200 一對（橫斷面指數 1.19，回本餘裕 1.31）。另外 E339（Sonnet 持平）與 E338（5.6 Terra 時點）有錯，E341 的數字無法復現。

## 2. 步驟 1：q 的口徑

**結果：Arch 三個層級的模型參數、SLO、參考請求與校準倍數，在 Perf 頁 15 欄（5 世代 × 3 層級）的公式逐列比對後，完全不隨世代變動。** 只有硬體規格與硬體校準隨世代變動。逐格清單見 `docs/evidence/20261015_世代價格A/步驟1_q口徑.md`。

- 固定（只隨層級變）：啟用參數、層數、d_model、專家數、KV、注意力結構（Perf 第 28–39 列 → Arch）；SLO 65 tok/s、TTFT 3 秒、參考 ISL 16,384／OSL 2,048、MTP、接受率與記憶體／通訊效率（第 41–62 列 → Serving）；Tech_Registry 五個倍數（全為 1）。
- 隨世代變（＝新硬體）：GPU 數／架、峰值算力、HBM 容量與頻寬、EP 頻寬與基準寬度、專家權重精度（Hopper FP8＝1 byte；GB200 起 NVFP4＝0.5625 byte）、prefill 實例 GPU 數（Spec_Rack）；η_d、每層延遲、η_p 的校準（Calib 第 70–72 列；Hopper 有 1.5／1.5／0.4997 倍，其後為 1）；每 GW 機架數（DC_Cost，由每架配電功率決定）；因而派生的 TP 度、EP 寬度、批次 B*。
- q＝Sol 的 prefill＋decode 總 token（8:1）每 GW 年產出，新世代÷舊世代（L1!D58:D60，來自 Interface 基準欄 D／G／J／M）。

**q 對應哪一種價格口徑（給 Q3 的依據，我沒有替 Project 決定）：** q 衡量的是同一個模型、同樣的服務品質門檻下，新機架每 MW 多服務多少 token。模型沒有變強，變的只有硬體（包括 GB200 起改用 NVFP4 這種硬體自帶的精度）。因此與 q 配對的價格，邏輯上只能是「同等能力的 token 價格」。若改配「層級牌價」（每代旗艦或中階模型上市價），價格裡含有「新一代模型更強」的成分，而 q 沒有這個成分，兩者衡量的不是同一件事：層級牌價持平時，意思是「新世代賣的是更強的模型、賣同一個價」，那麼 q 低估了每 MW 的能力提升；層級牌價下降時，則可能把同一個能力進步算了兩次。算力租賃價（每 GPU 小時）則不需要 q，因為價格本身已包含硬體速度，只需要換算每 MW 的 GPU 數。

## 8. 待 Project 判斷

**Q1　契約第 4 節「中性 q × p ≈ 1」改為情境標籤，或維持為基準？**
- 選項 A：維持「q×p≈1＝中性」。影響：要讓三對世代的指數＝1，需要價格每年變化 −57%／−60%／−32%，即「中性」其實要求價格大幅下降；與層級牌價的近期實證（持平到小降）相差很遠，中性情境反而像是悲觀情境。
- 選項 B：改為情境標籤，q×p 的值當輸出，不當定義；以三個標籤（高於／近於／低於回本餘裕＝1）取代「中性」。影響：下游沒有單一基準，要自己選 p 的口徑。
- 替代定義候選：(1) 回本餘裕＝1（指數＝持有成本比 0.910／1.233／1.123）；(2) 以實證 p 的區間中位數定義中性；(3) 以「每 MW 收入持平於上一世代」改稱「持平情境」，不稱中性。選 (1) 與「收入指數＝1」會差 −9%～+23%（成本比）。

**Q2　壽命內衰減（g，進 L_price）與世代間價格變化（g_gen）是否分開？資料能否區分？**
- 現況：Cap_In I-1 的 g 來自 E338–E341，那是「各模型上市價的前後比較」，也就是世代／模型更替的價格變化，卻被用在 L_price（同一批硬體、壽命 6 年內的單位價格衰減）。
- 資料能部分區分：本報告蒐集到的「同一模型壽命內降價」事件只有 7 筆（o3 −80%、Gemini 1.5 Pro −64%／−52%、Luna −80%、Terra −20%、Sol −20%／−33%，另有 AWS P5 −44% 與 Sonnet 5 取消漲價），但沒有分母（多少模型從沒降價；GPT-4、Sonnet 4.x 上市後牌價都沒動），所以算不出一個壽命內衰減率，只能說「下降主要發生在換新模型時，壽命內多為不動或一次性大降價」。
- 選項：(i) 不分開，沿用 g（影響：L_price 若以換代降幅衰減，可能高估壽命內衰減）；(ii) 分開並各設基準與區間（影響：多一個 Assumed 參數，區間仍寬）；(iii) 分開，壽命內衰減先設較小（區間含 0），g_gen 另列。

**Q3　g_gen 的價格口徑**（依步驟 1：q 對應「同等能力 token 價格」）
- 口徑 1：同等能力價格（與 q 邏輯一致）。實證 −79%～−97%／年，指數 0.005～0.8，含演算法效率與競價，不能原樣當硬體 g。若採用，需要把「硬體可歸因部分」另外拆出（Gundlach 等估演算法約 3 倍／年），資料目前只有這一個粗估。
- 口徑 2：層級牌價（與 q 不完全一致）。實證落在門檻附近到上方，但取決於家別與時點；隱含假設是「新世代賣更強的模型、每層價格不變」，此時 q 低估能力提升。
- 口徑 3：算力租賃價（不需 q）。邏輯最乾淨，但 GB300、VR200 沒有公開價，現有橫斷面只能算 Hopper→GB200（指數 1.19）。
- 口徑 4：混合——以層級牌價當基準、以同等能力價格當下限情境、以租賃價當上限情境。影響：三個口徑要分欄，不得混用（契約第 4 節原則）。

**g_gen（或世代每 MW 價格指數）基準與區間候選**（只列候選，不推薦）：
- 候選 1：沿用現行 −10%（−25%～+5%）。理由：最近兩年層級牌價窗口落在 −3%～−16%（OpenAI 2024.3 起）。缺點：該窗口含 GPT-4o 以來的旗艦降價，與 2025 年後的持平不一致。
- 候選 2：基準 0%、區間 −30%～+15%。理由：GB300→VR200 一對三家為 +12%／−29%／+26%。缺點：Sonnet −29% 已跌破回本門檻。
- 候選 3：不設 g_gen，改用上列兩個門檻當輸出（見 Q6），由下游自選 p。

**Q6　是否在 L1 新增「世代每 MW 簽約收入指數」與「回本餘裕」？**
- 選項 A：新增指數與回本餘裕兩列（需要 p）。影響：Tokenomics 開始輸出含價格的每 MW 收入，與 L1 現行聲明「Tokenomics 不輸出每 MW 收入，下游自算」及第 1 節「產業基準」定位衝突，且價格口徑未定（Q3）。
- 選項 B：只新增兩個「門檻 g」（收入指數＝1、回本餘裕＝1 所需年價格變化率），只由 q、Δ、持有成本比決定，不含價格。影響：符合現行定位；Δ 成為新的 Assumed 參數（本報告給的基準與區間）。
- 選項 C：不新增，報告留作 Project 對照。

**其他需要 Project 決定的事：**
- Δ 基準與區間（第 5 節）是否採用；GB200→GB300 只有半年，是否該視為同一世代的改款。
- E338 的「中階」序列定義：2025 以前是旗艦，是否改成「旗艦」與「中階」兩條，並更正 5.6 Terra 時點。
- E339 Sonnet 持平、E341 數字是否更正（P-a2、P-a4）。
- 是否要求補查：Wayback 快照（需另一工具）、OpenAI o1／GPT-4.5 牌價、GB200／GB300 在 CoreWeave 的上市價、Artificial Analysis 的固定能力價格序列。
