# AL_UtilActual 證據原稿（唯讀查證，2026-10-23）

定義：整個推論服務機隊時間平均實際 token 吞吐 ÷ SLO 下穩態批次可達理論產能。現值 0.41，區間 0.30–0.65。
結論先講：**公開資料中沒有任何一筆直接量到這個口徑**。能用的只有「尖離峰比」換算與「分配／閒置」的間接證據。

## 換算式
時間平均負載（相對尖峰）= 平均 / 尖峰。若尖峰以 SLO 滿載、離峰機隊不縮減，則 AL_UtilActual ≈ 平均/尖峰 × （尖峰時段實際 ÷ 理論產能）。不確定性：(a) 尖峰是否真的滿載（多數機隊為突發與故障預留餘裕，會再乘 <1）；(b) 機隊是否離峰縮減（縮減則比值升高）；(c) 多模型分散部署的長尾閒置（Aegaeon）會再降低；(d) 各 trace 的負載單位是請求率而非 token 吞吐。

## 對區間的建議（供 chat 端判斷，非決定）
- 低 0.30：Coding 型尖谷（平均/尖峰 0.36）再乘尖峰餘裕與多模型長尾閒置。
- 基準 0.41：與 DynamoLLM 兩類負載之間（0.36–0.59）、再乘約 0.8 的餘裕／路由不均，約落 0.3–0.47，現值 0.41 在範圍內，**可保留，但標 Assumed／Analogy，不是量測值**。
- 高 0.65：Conversation 型 0.59 加上離峰縮減（DeepSeek 式把離峰節點轉去訓練，機隊占用更平）才可能達到；若算上外溢離峰回收，才可上看 0.65。
- 重要提醒：以上全是「請求率尖谷」換算，且都來自 Microsoft Azure 2023 前後 trace，與 2026 年代理式／批次負載（較平坦）可能不同；沒有任何來源直接支持 0.41 這個數。
