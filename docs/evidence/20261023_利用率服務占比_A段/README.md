## 結論先行

1. **三個輸入都沒有直接的量測值，現值全部可以保留，但都只是「合理範圍內的假設」。** 我沒有找到任何公開來源，直接量到「機隊時間平均產出 ÷ 理論產能」，或是 OpenAI 服務／免費占比的原文。建議區間與現值相同（表 1）。
2. **實際利用率 AL_UtilActual（0.41）**：最硬的證據是 Microsoft Azure 的生產負載紀錄（DynamoLLM 論文）：尖峰是平均的 1.7 倍（對話型）與 2.8 倍（程式型）。若機隊按尖峰配置，時間平均負載只有尖峰的 0.59 與 0.36；再乘「尖峰時段是否真的滿載」（我假設 0.7–1.0），得 0.25–0.59，中位 0.38。現值 0.41 落在其中。**這是類比推算，不是量測**，來源是 Azure 2023 年前後、以請求數（不是 token）計的紀錄。
3. **服務占比 B4_Serve（0.41）**：證據範圍 0.26–0.51。OpenAI 2024 約 0.26–0.29（Epoch）；OpenAI 2025「研發與推論約各半」（Epoch 2026-09，文字，無精確數）；Anthropic 2025 反推約 0.40（Epoch，作者自稱有推測成分）。現值在範圍中間，保留。
4. **一個需要 Project 注意的出處問題**：現值 0.41 的分母含「OpenAI 2025 訓練支出 $12B」（SRC_DEM_006）。活頁簿記載的來源只有 `openai_token_revenue.json`（內部檔），**我與子代理都找不到外部原文**；搜尋看到的 $12B 左右數字，疑與 Azure 推論累計 $12.43B 混淆（未證實）。因此 0.41 的分母沒有外部背書。我建議不要因此改值（另一條路徑 12.6÷(12.6+12)=0.51 與 Epoch「各半」同向），但要標「出處待補」，由 B 段取原文（待判斷 J5）。
5. **免費占比 B4_Free（0.46）**：唯一直接證據是現值本身的來源（The Information 2026-02，$3.9B ÷ $8.4B），付費牆，我們都沒讀到原文。免費層的 token 占比或算力占比，**已搜尋，未找到**任何來源；只有用戶數占比（約 81%–95%），口徑不同。保留 0.35／0.46／0.60。
6. **對回本判讀的方向**（粗估，不是模型輸出；細節在「建議區間」頁，每格是公式）：
   - 利用率越高越容易回本。以 2025 機隊損益兩平乘積 0.465 計，所需「價格實現度 L×m」在利用率 0.30／0.41／0.65 分別約為 1.82／1.33／0.84。
   - 服務占比越高越難回本。營收固定時，B4_Serve 0.30／0.41／0.60 對應「營收 ÷ 服務端持有成本」約 4.1／3.0／2.1 倍。
   - 免費占比越高，付費機隊越小：B4_Free 0.35／0.46／0.60 對應付費機隊占比 0.27／0.22／0.16。

## 4. 這份結論可能錯在哪裡
