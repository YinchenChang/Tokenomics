## 4. README 不符處

3. 第 4、5 點與 J5：未說明模型 SRC_DEM_006 在 v17.2 已記「15 組查詢未找到」，讀者會誤以為是 A 段新發現。

## 5. 另評

**(a) 口徑不同的證據是否被當成可直接換算？**
- U1：請求率尖峰÷平均，換算成 token 吞吐利用率需再乘「尖峰滿載度」。A 段已明說這是類比而非量測，標籤 Analogy 合理；但 0.7–1.0 完全是 Assumed、無來源，敏感度很大（0.25–0.59），README 已承認。屬已揭露。
- S19：12.6 含研究推論與 Microsoft 加價，與分母訓練 12 混用（見 S19）。證據頁只說「口徑不同，只作方向」，沒有說出「雙重計入」這一具體問題；0.51 作為範圍上緣的證據力應再降。**這是唯一我認為揭露不足的口徑問題。**
- S1：2024 年、且不含 Microsoft 自承擔之授權模型推論；A 段已寫。
- S4：Anthropic 推論為毛利反推，A 段已寫「somewhat speculative」。
- 其餘（U4、U8、U9、F2）A 段皆明標「口徑不同，只作參考」，未用於換算。

**(b) 未標示的不確定性**
1. 0.41 的唯一直接來源是付費牆文章（F1／SRC_DEM_004、005），且分母 $12B（SRC_DEM_006）無外部原文，模型與 A 段已承認，但 B4_Serve 的置信度寫「低–中」，而其分母無外部背書，個人認為應為「低」。
2. 表 1 的「與現值差異：無」是建議區間與現區間相同；證據範圍 0.26–0.51 的上緣 0.51 正是 S19 的問題值，若扣除則上緣約 0.50（S3 文字）／0.40，實質上高端 0.60 並無證據支持，只有「各半」的文字。A 段未說明 B4_Serve 高端 0.60 的依據。
3. 建議區間頁第 1 節的「中位 0.384」是 6 格網格的中位數，其意義取決於滿載度假設，不是統計量；README 已稱「中位 0.38」，可再補一句。
4. U1 的尖谷比來自單一 Azure 負載（2023 前後），2026 年代理式與批次負載較平坦，A 段第 4 節已列。

否。SemiAnalysis 只出現在 S8（經 Lambda Finance 二手），標「不採用」，也未影響任何區間。我另搜到 SemiAnalysis 圖表（Anthropic＋OpenAI 合計的預訓練 7%、後訓練 55%）與一則「訂閱占 Anthropic 推論算力逾 40%」的 2026-10-05 文章，皆未被 A 段收錄；前者為兩家合計、後者與本題間接相關，列為可能遺漏的線索，**我未讀原文**。另有一則「Anthropic CFO 稱多數算力用於研究」的 cryptobriefing 轉述，我的 fetch 失敗（DNS），未核對，亦列為潛在遺漏線索。
