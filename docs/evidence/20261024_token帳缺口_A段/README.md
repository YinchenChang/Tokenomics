## 結論先行

1. **「token 帳剩約 2.65 倍」是支出路線的數字；P×Q 營收用的是另一條路線。** TK 有兩個 token 帳：
   - 支出路線 `L1_TokLedger`：用推論支出 ÷ 持有成本 ÷ 計價倍數推回 token。2025 為 2.652，2026 Q2 為 3.019。
   - GW 路線 `L1_TokLedger_GW25`：用上線 GW × 服務占比 × 每 GW 產能推 token。2025 為 **1.520**（區間 0.45–5.26，跨過 1）。
   - `L1_RevGW_PQ_VR200` 的 Q＝每 GW 產能 × 服務占比 ×（1 − 免費）× 利用率 × 生產折減，與 GW 路線同構。
   - 但 L1 第 133 列的讀法（「實際營收約為該列 ÷ 本列」）引用的是支出路線，所以「÷3.0」高估了 P×Q 的折算幅度。
2. **GW 路線 2026 Q2 為 2.10。** 用 J7 的 Q2 季平均 2.34 GW（下界）加上 TK 的 2026 世代組合計算，區間 1.98–2.55，隨 GW 而變。
   - 從 2025 的 1.52 升到 2.10，原因是模型的每 GW 產能隨 Blackwell 占比上升 1.74 倍（6.68 → 11.6 × 10¹⁰ M tok／GW·年）。
   - 同期需求面付費 token 只增 2.61 倍，GW 增 2.07 倍。
3. **候選因子（逐項只改一個，其餘取 TK 現值；GW 路線起點 2.10）：**
   - S2 非 Hopper 世代的產能實現率（0.6／0.8）：1.31／1.70。**影響最大，沒有量測。**
   - D2 Codex 在 API 之外的 token（2／8／25 T／日）：1.95／1.62／1.10。
   - D1 API 的 Q2 季平均相對 3 月底時點值（1.15／1.35 倍）：1.87／1.64。
   - D3 每則 token（6,000／11,000）：1.90／1.53。
   - S1 2026 新增 GW 中對外服務的比例（0.2／0）：1.89／1.70。
4. **全部取基準時，GW 路線 token 帳約 1.01，接近閉合；但五個因子都是 Assumed。** 全取不利閉合的一端為 1.95，全取有利的一端為 0.41。支出路線同樣組合為 1.62（0.74–2.81）。
5. **必須為真（其他取基準時，單一因子要多大才閉合）：** Codex 在 API 外約 8.6 T／日；或每則 token 約 6,400；或 API 季平均倍數約 1.18。三者都不離譜，但都沒有直接證據。
6. **刪去的候選：** 「企業訊息漏算」——OpenAI 2025-08 的每日 30 億則已涵蓋免費、Plus、Pro、Enterprise、Team、Edu（Epoch 用量資料集原文），不是缺口來源。**降級的候選：** Sora 影片——Forbes 2025-11 估每天約 1,500 萬美元（OpenAI 未證實），2026 年初已關閉，只可能影響 2025 年與 2026 Q1，不影響 Q2。

## Judgment（LIGHT）

- **Stance：** 現在寫的「token 帳約 3.0、P×Q 營收約 ÷3」讀法高估了缺口。應改寫為 GW 路線：2025 為 1.5，2026 Q2 約 2.1（2.0–2.6）。以基準假設看，GW 路線的缺口可以由 Codex 的 API 外用量、API 季內成長與新世代產能爬坡合理解釋，**但沒有任何一項有直接量測**。
- **Confidence：** 路線判斷 High（公式結構可直接驗證）；缺口歸因 Low（五個因子全是 Assumed）。
- **基準情境與替代（粗略機率，Assumed）：**
  - 缺口主要在需求面漏算（Codex、API 季內成長），約 45%。
  - 主要在產能側（Blackwell 實現率、新 GW 偏訓練），約 35%。
  - 兩者都不足，另有未知來源（例如免費占比、利用率本身），約 20%。
- **最強反向證據與處理：** TK 已知 Hopper 的模型值約為實測的 0.27 倍（`Hopper 吞吐` 未結判斷題）。若照實測校準，模型產能會**上升**、缺口變大。這與 S2 的方向相反，所以 S2 只套在非 Hopper 世代，並保留這個衝突不解。
- **方向一致性檢查（第 10 條）：** 5 個因子中，D1–D3 讓需求變大、S1–S2 讓產能變小，全都朝「閉合」方向；反向的只有 Hopper 校準一項，沒有放進組合。所以組合「基準 1.01」**偏向閉合**，屬於樂觀讀法，應讀為上述條件都成立時的值。
- **覆蓋檢查（第 11 條）：**
  - [P] 每則 token、產能實現率、非文字工作負載（Sora、影像、語音）：已列；後者只定性。
  - [A] 需求恆等式（則數 × 每則 token；API 每分鐘 × 分鐘數）、兩條路線的恆等式：已做。
  - [I] OpenAI 揭露的誘因（成長宣傳、時點峰值、「超過」）：已標。
  - 未做：利用率與免費占比本身。這兩項 TK 已有區間；本段把它們當作既定值，屬於刻意排除，不是漏掉。
- **判定性證據（Invalidation）：**
  - OpenAI 公布 2026 年中的 API 每分鐘 token 或 Codex token 總量；
  - 或 OpenAI 的推論機隊利用率；
  - 或 Blackwell 在大型服務的實測吞吐。
- **實務意涵：** 對外引用 P×Q 時改用 GW 路線的折算：49.51 ÷ 2.10 ≈ 23.6 $B／GW·年，而不是 ÷3.02 ≈ 16.4。
