## 結論先行

1. **Oracle 與 Epoch 的算式都已重現。** Oracle：300 ÷ 5 年 ÷ 5GW ＝ 12.0（5GW 當 IT）；5GW 當設施換 IT 為 14.4；A 段用的 4.5GW 報導則為 13.3／16.0。四種讀法對 VR200（12.23）是 **0.98–1.31 倍**。Epoch：16 ÷ 1.25 ＝ 12.8，1.25 是 2024、2025 年底上線 GW（0.6、1.9）的線性內插，不是 Epoch 揭露的 GW；指數內插 1.13 則為 14.2。對 2025 組合 9.35 為 1.37／1.52。A 段「1.25GW 出處未知」更正為此。
2. **IREN 原文推翻了 A 段的一個說法。** 原文的每 MW 14–16 百萬美元是「不含 GPU 的全部 capex」＝資料中心本體 9–11＋叢集部署 3＋加速費用 2，不是資料中心本體。Tokenomics 廠房 capex（12.67）**不含**網路與叢集部署。所以：
   - 以本體 9–11 比，TK 廠房**偏高** 15–41%；本體加叢集部署（12–14），TK **落在區間內**。「TK 廠房可能偏低」**撤回**。
   - IT 設備：IREN 29.0（若叢集部署歸 IT 側則 32.0）對 TK 32.24，為 0.90–0.99。
   - 廠房改用 IREN 值對 TK GB300 持有成本的影響：−0.38 至 +0.33 $B/GW·年（約 ±3%），不改結論。
   - 營運費用下界 1.455（15%×9.70）有原文依據（扣電費、維修、其他直接營運費；不含企業管理費、財務費用、非現金項目）；TK 1.98 仍高 36%，原因未能拆開。
3. **機隊層級 1.37 與長約 0.89–0.93 的矛盾仍未解決，但有一個最可能的方向。** 長約隱含的租金約每 GPU 小時 **$2.3–2.7**（IREN GB300 $2.27、Nscale GB300 $2.72、Epoch 12.8 在 2025 組合下 $2.31、H100 指數 $2.5–3.2），幾乎不隨世代變；TK 持有成本每 GPU 小時卻從 Hopper $1.54 升到 GB300 $2.55、VR200 $4.78。於是倍數隨世代由 >1（Hopper 為主的 2025 機隊）降到 <1（GB300）。這同時解釋兩邊，但資料點少，且有反例（CoreWeave 2026Q2 隱含 $1.5；Oracle→VR200 若交付 VR200 則 $4.7）。
4. **若堅持把 12.8 拉回 0.93，所需條件**：全年雲端支出 16 中須有 $5.1B（32%；用指數 GW 為 $6.2B、39%）不是 GPU 容量租金。可能的原因（非 GPU 服務與研究、Hopper 舊約、Azure 轉售加價、GW 口徑、非現金額度、預付未上線）逐項評估列於「B 段」頁第 2 節；彼此方向相反、量級都能到 ±20–30%，**現有資料無法分離**。缺的輸入：OpenAI 雲端帳單分項、各供應商實付 GPU 小時單價（已搜尋，未找到）。
5. **CoreWeave 2026Q2：** 營業成本占營收 34%，與 TK「廠房側成本占持有成本」約 30% 量級吻合；折舊占營收 54%，TK 組合 IT 帳面折舊占 47%。營收年化 ÷ 平均 active power（1.25GW）＝ 8.24，為 TK 組合的 0.88；隱含 $1.49／GPU-hr，低於現貨指數，爬坡落差與口徑不可分離。**Nebius：** 營業成本占 23%、折舊占 45%；耐用年限 4→5 年使帳面折舊率降約 20%。
6. **TK 哪一項偏（更新，仍只提出）：** 折現率 10% 對出租方 3–8%（口徑差，主因，約占 IREN 差額 55%）；營運費用可能偏高約 0.5（約占 45%）；廠房 capex 不再列為偏低。
