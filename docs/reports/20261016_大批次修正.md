### G1 追查結果與判定依據

Calib C68（Hopper EP 通訊項倍數 1.5）的來源：

- 自 v5.2（2026-09-30）建檔即存在，標記「Assumed 1.5，區間 1–3；Hopper EP 跨節點走 IB」，沒有來源。
- v5.2–v5.12 每層固定延遲＝240.4 µs（擬合值 160.28 × 1.5），**不是** DeepSeek 論文的 241.92 µs。241.92 µs 在 repo 內首見於 2026-10-16 的大批次查證。v10.2 把擬合改為 161.19 µs 後，乘積變成 241.78 µs，與 241.92 µs 只差 0.06%，是後來才出現的巧合。
- 物理上，固定延遲（每層 all-to-all 延遲、同步）與 EP 通訊項（頻寬 × 資料量）不是同一個量，沒有結構上的重複計算。

判定：**無法確認重複計算 → C68 維持 1.5**。為了讓 chat 端看到「若改成 1.0 會怎樣」，用 scratch 複本試算（不寫入 Excel），結果列在第 5 節。

### G4 軟上限

Checks 驗證項 F 欄結果：1＝通過、0＝失敗、「警示」＝軟上限警示、「—」＝不適用。V1–V3 的規則：模型 ÷ 實測低於下限＝失敗；高於 1（模型超過 MLPerf 實測）但不超過上限（I 欄）＝**警示**；其餘＝通過。V1–V3 的通過帶下限 0、上限寫在 I 欄；MLPerf server 的 TPOT 80 ms 是 p99，模型取平均，所以略高於實測不視為失敗。V4–V6 的上限仍是硬上限（超過＝失敗）。
