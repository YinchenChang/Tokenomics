## 4. K2 機制與自測

**機制**
1. `RNG_Version`：端點產生當下的版本（常數）；`RNG_Current`：由 README 版本字串即時取出；兩者不同就過期。
2. `RNG_OutCount`：對每個名稱的基準列做「基準是否在 Lo／Hi 之內」的格數計算（容差 1e-9）；上游輸入改動後基準跑出區間，格數上升。
3. `RNG_StaleFlag`：版本一致且 OutCount＝0 顯示「一致」，否則顯示「區間過期」。
4. Checks RG1（版本不一致 → 1）、RG2（任一格出區間 → 1），皆為 WARN，計入 `GOV_Warnings`，不阻擋。
5. parity：`test_v1300_ranges_equal_scenarios` 以 `scenarios.yaml` 的兩個端點情境重算，要求每個 `RNG_*_Lo／_Hi` 格等於重算值，且名單相等。

**自測（三種刻意改壞，測試都必須失敗）**

| 改壞方式 | 結果 |
|---|---|
| (a) 一個端點常數加 1e-6（`RNG_IF_AllocQ1_Hi`） | 測試失敗，抓到 `IF_AllocQ1` 該格不符 |
| (b) 改動上游輸入（研發世代組合 AL_RDMixHopper、AL_RDMixGB200），端點不更新 | 測試失敗，抓到 45 格以上不符 |
| (c) 拿掉一組區間（`RNG_IF_AllocQ2_Lo`） | 測試失敗，抓到名稱缺漏 |

另外 `test_v1300_stale_flag_fires` 驗證：舊版本字串 → 「區間過期」、RG1＝1、GOV_Warnings 282 → 283；端點改成大於基準 → OutCount 1、「區間過期」、RG2＝1、GOV_Warnings 282 → 283。

**修正記錄（本輪中途）**：第一版 RG2 直接回傳出區間的格數並加進 `GOV_Warnings`，在舊 SLO 視圖改動上游輸入時會一次加上 225 格，使 3 個既有期望值不符。改為 RG2＝「有任何格出區間則 1」，格數仍由 `RNG_OutCount` 提供。見第 7 節測試變更。
