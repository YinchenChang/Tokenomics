## 4. 判讀列與總檢查

- Cap_In C242 的公式 L 側讀 `L1_LTotalFleetVDisc`（＋Lo／Hi），所需 L 側讀 `L1_LReqFleet_IdNoK`（＋Lo／Hi），三態規則為 Hi < 所需 Lo＝未回本、Lo > 所需 Hi＝回本、其餘未定。
- C242 顯示「未定（區間重疊；基準 L 0.759 對所需 L 0.756）」，與預期一致。D242、E242 分別為低端 0.473 對 0.490、高端 1.138 對 0.922，G242 寫明基準比值 1.003。
- GOV_Errors＝0；RNG_StaleFlag＝「一致」。
- 全部工作表掃描錯誤值（#REF!、#DIV/0!、#VALUE!、#NAME? 等）：0 格。

## 5. 觀察（不影響結論）

1. Cap_In G242 說明欄開頭仍保留舊句「基準 0.6426 ≥ 0.3645 → 回本（L_total 口徑）」，是更早版本留下的歷史文字，容易被誤讀成現行結論。報告雖說明舊文字保留，但建議 Project 考慮加註或移到尾端。
2. 建置報告已列的待判斷事項我同意：WACC 低端（8%）折現較輕，使低端組合 L 偏高；與 g 低端方向相反，區間可能偏窄。這屬判斷類，非查核缺陷。
3. 基準比值 1.003，結論仍是「未定」，距離邊界極近，對任何小幅輸入變動都敏感，下游引用時需注意。
