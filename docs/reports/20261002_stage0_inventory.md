## 1. 本輪做了什麼、為什麼

治理規劃的 Stage 0 是「先盤點、再遷移」：在把原始數據搬進第 0 層 Source 之前，先知道 324 列藍字輸入各屬哪一類、每一列會影響哪些下游名稱、哪些列對結果最敏感（決定之後查核的先後）。本輪由 CC 做工程部分：

1. 依現有標記文字，把藍字輸入機械地做初步分類（沒有標記的列只標「待分類」，不判定）。
2. 建立靜態依賴圖：每一列藍字會影響哪些 `IF_` 名稱、哪些主要輸出。
3. 對 14 個主要輸出（O01–O14）逐列擾動 ±10%，算出彈性並排序。
4. 把以上產出為一本 Excel（盤點檔）與一支可重跑的程式（Stage 1 Gate 1 可重用，例如「改一筆輸入，列出受影響範圍」）。
5. 順手完成第 9 輪遺留的網站小修（Block 5 任務表橫向捲動）。

判斷類的事（待分類各列屬哪一類、遷入哪個 SRC 分頁、來源等級與立場、敏感度門檻是否合理）一律沒有碰，留給 chat 端。
