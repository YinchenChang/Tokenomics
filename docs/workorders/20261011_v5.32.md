## 0. 起因
- `CTL_Monetize`（Cap_In C64，變現率 m）＝付費 token 平均實收單價 ÷ OpenAI 有效單價（表列 ×（1−折扣））。基準 1、區間 0.3–1.0、標記 Assumed，模型自註「無實證（缺每位付費用戶年 token 消耗量）」。
- m 與 L 共同決定回本：`L1_FleetBreakeven`＝0.1505（VR200），在 IF_Util 0.6、CTL_ProdDerate 0.85 下需 L × m ≥ 0.295；若實際利用率 × 折減只有 0.35（`L1_GapUtil` 的新輸入），且 L 在類比區間下緣 0.42，則需 m ≥ 1.02。m 是目前回本結論最弱、又最承重的輸入之一。
- 免費用戶不在 m 內（Theory_Rev B 節：免費服務營收 0；免費占比在 Cap_In 第 29 列）。m 偏離 1 的主要來源（chat 端判斷，依重要性）：(1) 訂閱吃到飽（重度用戶的 token 價值遠高於月費；輕度用戶則 m > 1）；(2) token 組合與快取命中（實際輸入占比、快取命中率高於參考請求時，每 token 實收價較低）；(3) 大客戶議價超過已扣的 20%；(4) 通路分潤（Azure、Bedrock、Vertex）；(5) 付費帳戶內免費額度、試用與新創點數。
- 最直接的追蹤式：**隱含 m ＝ 付費營收 ÷（付費用戶數 × 每付費用戶年 token 用量 × OpenAI 有效單價）**，訂閱與 API 兩條路線分開算。
