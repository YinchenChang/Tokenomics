## 6. 待 Project 判斷

1. **檔名日期**：工作單產出欄寫 `20261021`，同一欄又說「日期用建置當天」。建置日是 2026-10-20，所以檔名用 `20261020_Tokenomics_v17.1.xlsx`。如要 20261021，改名即可（README B5、`RNG_Version`、快照、ranges、fingerprint 的版本字串也要跟著改，建議重建而不是改名）。
2. **`restore_log` 驗收寫「皆為 0」**：unmatched 是 0；「Excel value kept over code default」是 41，與 v17.0、v16.0 完全相同。這 41 格是 Excel 擁有的輸入（例如 Spec_Rack G23 程式預設 73、Excel 70）與 builder 預設值長期不同。v17.0 報告同樣寫 41。請確認以後驗收條件改寫為「不得多於上一版（41）」。
3. **版本字串差異**：CLAUDE.md 第 4a 節與工作單都說差異只能是標籤文字，但新版必然改 README 版本字串（A1、B5）、新增一列 README 說明、以及 `RNG_Version`／`RNG_Current`（Alloc C177／C178）。已照 v15.1 等前例處理並全部列在表 2；請確認是否接受，或要求 v17.1 不加 README 新列。

5. **寫死的現值再次過時的風險**：W3 開頭的「L 0.759 對所需 L 0.756」與 W5、W6 的 v17.0 現值都是寫死的數字（已標「v17.0」），下次主口徑數值改變時又會過時。工作單的做法（指向 C 欄／C–E 欄為準）已降低風險，但仍建議以後的說明文字以公式串接或只指向儲存格。
