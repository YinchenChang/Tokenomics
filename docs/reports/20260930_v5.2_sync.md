[Tokenomics 回報] v5.2 同步｜第 1 輪｜2026-09-30

## 一句話結論

v5.2 已可由「公式引擎」直接計算：8,427 個公式格在基準與 5 個情境下，與 LibreOffice 重算結果全部一致（不符 0 格）。網站新增 Block 2 頁與 Calib 驗證表。有 5 件事需要 Excel 端處理（見文末），本輪沒有改動 Excel。

## 1. 本輪做了什麼、為什麼

- 依 CLAUDE.md，Excel 是唯一事實來源；本 repo 只執行與呈現它。所以新增 `engine/`：載入 xlsx，用公式引擎重算，不手抄任何公式。
- 新增一致性測試（parity）：把引擎算出的每一格，跟 LibreOffice 獨立重算的結果逐格比對。
- 新增 CI：每次推送自動跑上述測試，任何一格不符就失敗，並列出前 20 個不符格（頁名、座標、引擎值、Excel 值）。
- 新增網站的 Block 2 頁與 Calib 驗證表。
- 依規範停用 v4 手抄公式（見第 4 節）。

引擎選型：試了 `formulas` 與 `pycel` 兩套（同一台機器實測）。

| 引擎 | 基準格數比對 | 全簿重算時間 |
|---|---|---|
| formulas 1.3.4（首選） | 8,427 格全對 | 載入 21.5 秒、每次重算 5.9 秒（未達 2 秒門檻） |
| pycel 1.0b30（備選，已採用） | 8,427 格全對 | 建構（含全簿重算）約 9.6 秒一次；之後「全簿強制重算」0.12 秒；改一個輸入後重算 0.05–0.13 秒 |

依「parity 全過且單次全簿重算 < 2 秒」的標準，採用 pycel。

## 2. 函數覆蓋結果

v5.2 用到的 12 種函數（IF、INDEX、MAX、MIN、ISNUMBER、CEILING、FLOOR、ABS、CHOOSE、AND、TEXT、COUNTIF）加上運算子 `^`、`&`，以及文字回傳、文字比較、含中文頁名的跨頁引用、INDEX 一維取值：全部支援。

- 為此另外寫了 61 個小式子（含邊界情形，例如負數、空白格、文字與數字比較、`"SLO 不可達"` 比對），逐式與 LibreOffice 對照：61 個全部一致。
- 發現並補上 1 個語意缺口：`TEXT(x,"0.0")` 遇到剛好對半的值（例如 0.25、2.675），pycel 內建的進位方式與 Excel 不同（Excel 是 0.3、2.68）。已在引擎層補上與 Excel 相同的進位（`engine/excel_semantics.py`），只修語意，沒有新增任何計算。目前 Excel 內 `TEXT` 只出現在 Checks 頁 2 格，受影響格數：0（現值不在對半點上）。
- 沒有任何格因函數不支援而無法計算，受影響格數：0。
- 引擎的兩個已知陷阱（已在引擎內處理，並有測試把關）：
  1. pycel 冷啟動時，公式格會直接回傳檔內的快取值而不重算（實測 3,729 格的最後幾位數不同）。若不處理，基準比對等於「快取值比對快取值」。引擎現在建構時一律強制全簿重算。
  2. 在依賴格尚未建立前就改輸入，之後會讀回舊值。引擎建構時已先建好全簿計算圖。

## 3. Parity 結果

比對範圍：全部 8,427 個公式格；數值容差為相對誤差 1e-9 或絕對誤差 1e-12，文字必須完全一致。基準是 LibreOffice headless 重算的結果。

| 情境 | 比對格數 | 不符格數 | 最大相對誤差 | 該情境改變的公式格數 |
|---|---|---|---|---|
| 基準 | 8,427 | 0 | 5.0e-15 | — |
| a) Serving!C16＝2 | 8,427 | 0 | 5.0e-15 | 967（其中 Interface 162） |
| b) Serving!C18＝0.7 | 8,427 | 0 | 4.9e-15 | 2,140（Interface 351） |
| c) Arch!E20＝3 | 8,427 | 0 | 5.0e-15 | 118（Interface 15） |
| d) Inputs!E6＝1 | 8,427 | 0 | 4.7e-15 | 1,693（Interface 411） |
| e) Serving!C17＝0.8 | 8,427 | 0 | 4.8e-15 | 182（Interface 1） |

- 最大相對誤差是「全部數值格」中的最大值；約 5e-15 是 LibreOffice 存檔只保留 15 位有效數字造成的，遠小於容差 1e-9。
- 錯誤值（`#REF!`、`#DIV/0!` 等）：基準與 5 個情境都是 0 格。沒有循環參照。
- 具名範圍：40 個全部存在，attr_text 與 workbook.xml 一致，且與 LibreOffice 存檔後的版本一致；Block 2 的 28 個（9 種前綴 × Luna／Sol／Astra ＋ `IF_Util`）逐一確認存在，且都能取值、無錯誤值。
- 情境測試有「防空轉」檢查：每個情境都確實改變了輸出，不是換了輸入卻沒影響。
- 「世代 × 層級」組合：Interface 一次算出 5 世代 × 3 成本情境 × 3 層級，每個情境都已涵蓋，沒有另外列組合。
- 測試總計 74 項全過（parity 72＋網站 2），本機約 5.5 分鐘。

## 6. 發現的 Excel 問題與需要 Excel 端處理的事項（本輪未改 Excel）

1. **Calib H 節沒有逐點的「量測平台」列。** F 節有（第 19 列），H 節沒有。網站現在改取 H 節的節標題（「MLPerf Inference DeepSeek-R1（MLCommons 稽核；提交者 NVIDIA 為利害關係方）」）顯示。建議 H 節補一列，並在列上註明每點的提交者。
2. **「推導鏈」無法在 Block 2 頁顯示。** 依 CLAUDE.md 1a，網站要依序露出中間物理量（權重讀取時間、算力時間、批次、固定延遲等）；但本輪指示 Block 2 頁只能讀 Interface 具名範圍，而這些中間量在 Perf／Calib 頁、沒有具名範圍。建議 Excel 端為關鍵中間量加具名範圍（或標 `key`），由 Andy 決定要露出哪幾項。
3. **缺少具名範圍的地方，網站是靠「欄 A 標籤」找位置**：Interface 的世代與成本情境表頭、Calib 的驗證表（F 節、H 節）。若標籤文字被改，網站會報錯。建議補上具名範圍（例如世代表頭、成本情境表頭、Calib 各驗證列）。
4. **decode $/M 沒有分「思考」與「可見輸出」。** CLAUDE.md 1a 要求成本要標明 token 類型（新鮮輸入、快取輸入、思考、可見輸出）；目前 Excel 只有新鮮 prefill、快取 prefill、decode 三類。網站照 Excel 顯示，不自行拆分。
5. **小問題（請 Andy 或 chat 端確認）：**
   - Checks 頁 E9、E10 的公式把外部參照數字（10.5、3.57）直接寫在公式裡，與 C 欄重複；C 欄改了、文字不會跟著變。
   - Checks 頁「SLO 不可達的欄數」目前為 0，備註寫「Hopper × 大模型預期不可達」；請確認 0 是預期結果。
   - Checks 頁最後一列與部分來源欄仍引用「v4 Config」，v5.2 已無此頁。

## 7. 給 Andy 的說明：這輪的結果代表什麼、不代表什麼

- 代表：網站與引擎算出的數字，與 Excel（以 LibreOffice 重算）一致，且改 5 種輸入後仍一致。
- 不代表：Excel 本身的假設正確。Analogy／Assumed 的參數（例如利用率 60%、生產折減 1.0）沒有被本輪驗證或修改。
- 測試以 LibreOffice 為「Excel 的替身」；尚未用真正的 Microsoft Excel 再核一次。兩者在本模型用到的函數上一致，但 Excel 是最終依據。
