## 1. 本輪做了什麼、為什麼

依 Andy 2026-10-18 的 L 定義（各世代從自己的起點算）與 2026-10-21 的 m 定義（只有收入面），把 Interface 第 321–328 列的 8 個「自算 L、m」情境名稱（`IFW_*_LifeSelf`）改成：

　**每 GW 理論營收（含有效牌價）× 該世代的折現 L × 收入面 m（`L1_M`＝1.343）**

- 新增工程類名稱 `L1_LDiscGen`（Cap_In C322:F322，四個世代的折現 L：Hopper 0.8439、GB200 0.7326、GB300 0.6988、VR200 0.6988）。下游契約不收這個名稱。
- Rubin Ultra 欄（O–Q）起點晚於錨點，沿用 VR200 的 L（0.6988）。說明寫在 Interface 的 Z 欄（見待判斷 5）。
- 結果：LifeSelf 比 v20.0 大 3.18–3.84 倍（Hopper 3.840、GB200 3.334、其餘 3.180），原因是舊口徑乘的是 token 帳診斷（`L1_MFleet`＝0.448），新口徑乘的是 m（1.343），而 L 由 0.660 換成各世代折現 L。仍是理想上限、不回流、不建議下游作為基準。
- `L1_PriceReqBE`（回本所需實收單價）的 L 由 `L1_LTotal`（0.660）改成主口徑 `L1_LTotalFleetVDisc`（0.759）：基準 1.880 → 1.634 美元／M token（低 1.131 → 1.089，高 3.084 → 2.591）。機隊實收單價 0.61 仍低於所需，判讀仍為「未回本」。成本範圍沒動（仍是 `L1_FleetBreakeven2025`，待判斷 3）。
- Cap_In 第 238 列的判讀改讀主口徑 L（0.759），字樣仍是「區間內（0.3–1.0）」；`C233` 本身沒改。

區間（依 J6，不新增 `_Lo`／`_Hi` 名稱，以文字列出）：各世代折現 L 低端 0.445–0.588、高端 1.080–1.329（Cap_In 第 323、324 列）；m 低 0.810、高 1.595（`L1_M_Lo`／`_Hi`）。

## 4. 待 Project 判斷

1. **W2 事前值與實際值的差超過門檻（1e-6）。** 實際 1.634248／1.089139／2.590736，工作單 1.63424／1.08913／2.59072，絕對差 8.0e-6／8.6e-6／1.6e-5。原因：工作單事前值是 1.87980 × 0.659506 ÷ 0.758597 這種四捨五入乘數的算式；用活頁簿精確值（1.879796179 × 0.659505673 ÷ 0.758597367）得 1.634248019，與活頁簿一致。公式與工作單逐字相同，**未改任何公式**。請決定：把工作單事前值更正為 1.63425／1.08914／2.59074，或接受 ≤3e-5 相對容差。我已先照工作單繼續建置（公式沒有疑義，停下無法解決這個問題），所有數值檢查依此寫成「精確換算 1e-9」與「事前值 3e-5」兩項。
2. **前緣單價列（325–328）套 m 是近似**（J3 已採預設，標註在第 320 列標題）：m 以 OpenAI 有效牌價定義，前緣單價列的牌價基準不同；`IFW_RevGWFront_*_LifeSelf` 的數字請只作並列參考。
3. **`L1_PriceReqBE` 成本範圍仍是 `L1_FleetBreakeven2025`**（J4 已採預設）：v20.0 的「全部算力持有成本」口徑（`L1_HoldFleet25`）尚未套到這個名稱。若要同步，需另立一版（會再改 `L1_PriceReqBE` 三格）。
4. **第 93 列其餘說明文字仍是舊 L 口徑**：I、J、K、S 欄的「L_total」字樣未改（工作單未要求）；H93 的 0.498／1.692 本就是舊數字，我順手改成新端點 1.138／0.479（屬第 93 列說明文字，不影響數值）。若不想動 H93，請告知還原。
5. **Interface 沒有「說明欄」**：工作單第 W1-2 要求在「說明欄」寫明 O–Q（Rubin Ultra）取 VR200 的 L，但 Interface 的 R–Y 欄已是契約元資料。我新增 Z 欄（標題「說明（v20.1）」，Z4、Z321:Z328）寫明；內容同時寫在第 320 列以外的 Decisions SL56-01、README 與契約 v0.23。若偏好改放別處，請指定。
6. **Cap_In 第 238 列的 D／E 欄**：工作單只寫「`C233` 換成 `L1_LTotalFleetVDisc`」；D／E 原本讀 D233／E233（L_total 的低端／高端組合），我依相同對應改讀 `L1_LTotalFleetVDisc_Lo`／`_Hi`（0.479／1.138），結果「區間內／區間外」與舊口徑相同。
7. **成本情境欄（C／E、F／H 等「低成本／高成本」）共用同一個 L**：`L1_LDiscGen` 只有基準欄四格，所以每個世代的三個成本欄乘同一個 L_v 與同一個 m（與工作單公式一致，僅在此註明）。
8. **下游實際讀取情形**：本 repo 內沒有任何公式引用 `_LifeSelf`（測試看守）；`L1_PriceReqBE` 在本 repo 僅 L1 第 93 列的判讀與對照欄使用。下游公司模型（OpenAI、CRWV 等）是否讀 `L1_PriceReqBE`，需由 chat 端核對；逐名稱新舊值見 `docs/reports/20261023_v20.1_變動名稱.csv`。
