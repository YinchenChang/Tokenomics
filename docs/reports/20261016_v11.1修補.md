## 6. `IF_AmortDefault_Astra` 為什麼在 v11.0 上升 0.9%

公式鏈（`Amortize!C47` 等）：`IF_AmortDefault_x` ＝ 該層自下而上攤提 × 縮放倍數，縮放倍數＝由上而下年化總額 ÷ 自下而上年化總額合計。由上而下總額不隨 η 改變；自下而上＝各層研發計畫成本 × 12 ÷ 商業壽命。因此 Astra 的 Default ≈ 由上而下總額 × **Astra 占三層計畫成本的比重**。

GB200 倍數 1 → 3.04（v11.0）後，三層的計畫成本都下降，但 Luna（−31%）與 Sol（−24%）降得比 Astra（−20%）多，Astra 的占比由 82.45% 升到 83.41%（+1.2%），總額不變，所以 Astra 的 Default 反而上升約 0.9%（GB200 基準欄 2.0143 → 2.0326），同時 `IF_AmortBU_Astra` 本身下降約 20%。方向合理，不是錯誤，只是 v11.0 報告沒有說明。v12.0（3.04 → 2.36）把這個占比小幅拉回（83.41% → 83.24%），Astra Default 2.0326 → 2.0295（−0.15%）。
