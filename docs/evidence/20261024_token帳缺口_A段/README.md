## 結論先行

1. **「token 帳剩約 2.65 倍」是支出路線的數字；P×Q 營收用的是另一條路線。**
   - **支出路線** `L1_TokLedger`：推論支出 ÷ 持有成本 ÷ 計價倍數 1.8，換成服務 GW，再依 token 比切分付費與免費。2025 為 2.652，2026 Q2 為 3.019。
   - **GW 路線** `L1_TokLedger_GW25`：上線 GW × 服務占比 ×（1 − 免費）× 每 GW 產能 × 利用率 × 生產折減。2025 為 **1.520**（區間 0.45–5.26，跨過 1）。
   - **P×Q 的 Q 與 GW 路線的每 GW 因子鏈相同，有兩處差異：** Q 的生產折減用 VR200 重解比 0.806（GW 路線用 0.85）；Q 只算 VR200 一代，token 帳用機隊世代組合。
   - L1 第 133 列的讀法（「實際營收約為該列 ÷ 本列」）引用的是支出路線。支出路線含計價倍數這個價格殘差，切分方式也不同（有效付費 92.7% 對 54%），兩條路線因此差 1.44 倍。結論：「÷3.0」高估了 P×Q 的折算幅度。
2. **GW 路線 2026 Q2 為 2.10，生產折減改用 0.806 時為 1.99。**
   - 用的是 J7 的 Q2 季平均 2.34 GW（中占比 × Epoch 日期），J7 六組情境為 2.21–2.85，對應 1.98–2.55。
   - 從 2025 的 1.52 升到 2.10，原因是：模型的每 GW 產能隨 Blackwell 占比上升 1.74 倍，GW 增 2.07 倍；同期需求面付費 token 只增 2.61 倍。
3. **候選因子（從起點 2.10 逐項只改一個，其餘取 TK 現值）：**

   | 因子 | 取值（基準／利於閉合端） | GW 路線 token 帳 |
   |---|---|---|
   | S2 非 Hopper 世代的產能實現率 | 0.8／0.6 | 1.70／1.31（影響最大，無量測） |
   | D2 Codex 在 API 之外的 token | 8／25 T／日 | 1.62／1.10 |
   | D1 API 的 Q2 季平均 ÷ 3 月底時點值 | 1.15／1.35 倍 | 1.87／1.64 |
   | D3 每則 token | 6,000／11,000 | 1.90／1.53 |
   | S1 2026 新增 GW 中對外服務的比例 | 0.2／0 | 1.89／1.70 |
   | D4 每日則數改以 2025-08 的 30 億為底（42.9 億） | — | 2.02（小幅） |
   | **R2 免費占比改用 TK 的 2026 情境 0.34（反向因子）** | — | **2.56**（缺口變大） |

4. **組合：五個因子全取基準時約 1.01；再加上反向的免費占比 0.34，變成 1.24。** 全取不利閉合的一端為 1.95，全取有利的一端為 0.41。支出路線同樣組合為 1.62（0.74–2.81）。五個因子與 0.34 都是 Assumed 或情境值。
5. **必須為真（兩種讀法都要看）：**
   - **從起點只動一個因子就閉合：** Codex 在 API 之外約 30 T／日；或每則約 24,800 token；或 API 季平均是 3 月底的 2.39 倍。三者單獨都偏高，**單一因子解釋不了缺口**。
   - **其他四個因子已取基準時：** Codex 約 8.6 T／日、每則約 6,400、或 API 倍數約 1.18。這是條件式，因為基準組合本身已約為 1，不能當作「三者都不離譜」的證據。
6. **候選調整（r1）：**
   - **企業訊息：** 原本刪去，改列小幅候選。2025-08 的 30 億則已涵蓋企業方案，但 TK 的底是 2025-07 的 25 億則；改以 30 億為底，token 帳 2.10 → 2.02。
   - **Sora：** 原本降級，改列為產能側、有利閉合的候選。App 在 2026-04-26 才關閉，API 到 2026-09-24，所以會影響 Q2。成本只有 Forbes 2025-11 的估算（每天約 1,500 萬美元，OpenAI 未證實），未量化。

## Judgment（LIGHT）

- **Stance：**
  - 現行「token 帳約 3.0、P×Q 營收約 ÷3」的讀法高估了缺口，應改寫為 GW 路線：2025 為 1.5，2026 Q2 約 2.0–2.1。
  - 剩下的缺口沒有單一因子能解釋。要閉合，需要需求面漏算（Codex、API 季內成長）與產能側（新世代實現率、新 GW 偏訓練）同時成立，而且免費占比沒有降到 0.34。這些都沒有直接量測。
- **Confidence：** 路線判斷 High（公式結構可直接驗證）；缺口歸因 Low。
- **基準情境與替代（粗略機率，全為 Assumed，無依據可量化）：**
  - 需求面與產能側各占一部分，加起來可接近閉合：約 45%。
  - 主要在產能側：約 35%。
  - 兩者都不足，另有未知來源：約 20%。
- **最強反向證據與處理：**
  1. **TK 的 2026 免費占比情境 0.34。** 若成立，缺口從 2.10 擴大為 2.56，基準組合從 1.01 變 1.24。若需求面的 ChatGPT 免費占比也同步下降，會部分抵銷。
  2. **Hopper 的模型值約為實測的 0.27 倍**（未結判斷題）。若照實測校準，模型產能上升、缺口變大，所以 S2 只套在非 Hopper 世代。
- **方向一致性檢查（第 10 條，r1 更正）：**
  - 五個候選因子 D1–D3、S1–S2 都朝「閉合」方向。
  - 已知的反向因子有兩個：免費占比 0.34、Hopper 校準。組合「1.01」沒有含入這兩者，屬於樂觀讀法；含入免費占比為 1.24。
  - 本段的選擇沒有收窄 Andy 留下的選項。
- **覆蓋檢查（第 11 條）：**
  - [P] 每則 token、產能實現率、非文字工作負載（Sora、影像、語音）：已列；非文字部分只定性。
  - [A] 需求恆等式（則數 × 每則 token；API 每分鐘 × 分鐘數）、兩條路線的恆等式：已做。
  - [I] OpenAI 揭露的誘因（成長宣傳、時點峰值、「超過」）：已標。
  - 利用率本身：TK 已有區間，本段當作既定值，屬刻意排除。
- **判定性證據（Invalidation）：**
  - OpenAI 公布 2026 年中的 API 每分鐘 token，或 Codex 的 token 總量；
  - 或 OpenAI 推論機隊的利用率；
  - 或 Blackwell 在大型服務的實測吞吐；
  - 或 2026 的實際免費占比。
- **實務意涵：** 對外引用 P×Q 時，改用 GW 路線的折算：49.51 ÷ 2.10 ≈ 23.6 $B／GW·年（生產折減用 0.806 時 ÷1.99 ≈ 24.9），不是 ÷3.02 ≈ 16.4。限制有兩個：
  - 用機隊比值折算 VR200 一代，前提是各世代的誤差一致。若缺口主要來自 S2，VR200 的 Q 應乘實現率，而不是除以 token 帳。
  - 上線 GW 數本身的誤差不在每 GW 的 Q 裡，不該拿來折算 Q。
